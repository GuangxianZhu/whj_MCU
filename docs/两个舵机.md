# 接两个 XL330：调研和计划

一个 XL330 已经能驱动。接第二个之前要做的事，按顺序：

1. **给第二个舵机改 ID**（改成 2），一次只接这一个。
2. **两个舵机串起来**（菊花链），电路（MCU、TXB0104、241）不用改。
3. **电源加强**：两个同时堵转时最多约 3 A，超过面包板能承受的范围。
4. **软件用 Sync Write / Sync Read**，一个包控制两个，两个同时动。

## 1. 调研结果

数据来自 ROBOTIS e-Manual（XL330-M288-T / XL330-M077-T 页面和 Protocol 2.0 页面）。

| 项目 | 数值 | 对我们的影响 |
|---|---|---|
| 推荐电压 | 5.0 V（范围 3.7–6.0 V） | 继续用现在的外部 5V |
| 堵转电流（5 V） | M288、M077 都是 1.47 A | 两个同时堵转约 3 A，电源至少 3 A，最好 4 A 以上 |
| 待机电流 | 17 mA | 不动时几乎不耗电 |
| ID | 地址 7，范围 0–252，出厂 1，存在 EEPROM | 扭矩关时才能改，改完断电也不会丢 |
| 波特率 | 地址 8：0 = 9600，1 = 57600（出厂），2 = 115200，3 = 1M，4 = 2M，5 = 3M，6 = 4M | 两个舵机必须一样 |
| Return Delay | 地址 9，单位 2 µs，出厂 250 = 500 µs | 决定每个应答前的等待 |
| Sync Write（0x83） | 包的 ID 必须是 FE，同一地址、同一长度写给多个舵机，**没有应答** | 两个舵机同时开始动 |
| Sync Read（0x82） | 包的 ID 必须是 FE，舵机**按包里 ID 的顺序**依次各回一个应答 | 一个包读两个位置 |
| 广播 ID FE | 只有 Ping、Sync Read、Bulk Read 会有应答 | 广播 Ping 能一次查出总线上有哪些 ID |

## 2. 硬件

### 连接

XL330 背面有两个一样的插座，内部是直通的。现在的排针（2B、3B、4B）→ 舵机线 → **舵机 A** → 再一根舵机线 → **舵机 B**。DATA 上拉还是只用 R1 一个。

### 电源（两种做法，选一种）

| 做法 | 怎么接 | 适合 |
|---|---|---|
| A：先不改 | 保持现在的接法，外部电源换成 5 V、3 A 以上 | 只装舵盘、不带负载的演示 |
| B：舵机电源不走面包板（推荐） | 外部电源的 + 和 − 用接线端子（或 ROBOTIS 的电源转接板）直接接到舵机线的 VDD 和 GND；拔掉 P3（V1 + → 3C），舵机的 5V 不再经过面包板；V1 − 和舵机 GND 仍要连通（P2 保留），保证共地 | 带负载、会堵转、以后再加舵机 |

#### 做法 B：同一个 5V 电源分成两路

“舵机电源不走面包板”不是说芯片不用 5V 了，而是把同一个电源分成两路：

```
                 ┌──→ 细线：V1 +（面包板）→ 241 VCC、TXB 的 HV、R1、R2   （几 mA）
外部 5V 电源 + ──┤
                 └──→ 粗线：直接到舵机线的 VDD（2 号线）               （最多约 3 A）

外部 5V 电源 − ──┬──→ V1 −（面包板）→ 所有芯片的 GND
                 └──→ 直接到舵机线的 GND（1 号线）

舵机线的 DATA（3 号线）照旧插在面包板 4B
```

- **芯片照常从面包板拿 5V。** 241、TXB、两个上拉电阻一共才几 mA。E1、E2、P4 这些线都不动。
- **只有舵机的大电流不走面包板。** 拔掉 P3（V1 + → 3C），舵机 VDD 直接从电源端子拿。
- **地还是要连在一起。** 舵机 GND 和面包板 GND 必须连通（P2 保留），否则 DATA 信号没有共同的参考电平。
- **实际怎么接：** “XL330 转杜邦线”一头是三根分开的杜邦头。VDD 和 GND 两根插到电源分出来的接线端子上（WAGO 那种按压式端子就很方便），DATA 那根照旧插在 4B。

#### 为什么面包板不行

1. **触点承受不了大电流。** 面包板里是弹簧片夹住针脚，一般按每个触点 1 A 左右估算。两个 XL330 同时用力约 3 A，触点会发热、接触电阻变大。
2. **电压会被拉低。** 大电流流过触点和细杜邦线有压降，舵机端电压一下掉下去，舵机可能复位，通信就断了。
3. **会干扰芯片供电。** 241 和舵机共用 V1 时，电机电流忽大忽小，241 的 VCC 也跟着抖。分成两路后芯片那一路是干净的。

只装舵盘、不带负载的演示电流很小，用做法 A（保持现在接法，电源 3 A 以上）就够了；要带负载、会堵转或再加舵机时再改成做法 B。

- 100 µF 电解电容（C4）可以换成 470 µF，放在离舵机近的地方。
- 动作时用万用表看一下舵机 VDD：低于 4.75 V 就说明电源或接线不够。

## 3. 第二个舵机改 ID（只接它一个）

用转发固件（`firmware/bridge/`）时，在 PC 串口助手里用 HEX 发下面的包。包是用 `tools/dxl_packet.py` 算的，和固件驱动算出来的一样。

| 步骤 | 发送 | 应该看到 |
|---|---|---|
| 1. 确认它是 ID 1 | `FF FF FD 00 01 03 00 01 19 4E`（ping 1） | 14 字节应答，`… 55 00 B0 04 …` |
| 2. 关扭矩 | `FF FF FD 00 01 06 00 03 40 00 00 DE E6` | 11 字节应答 |
| 3. ID 改成 2 | `FF FF FD 00 01 06 00 03 07 00 02 BD 63` | 一个应答 |
| 4. 确认新 ID | `FF FF FD 00 02 03 00 01 19 72`（ping 2） | 14 字节应答，第 5 个字节是 `02` |
| 5. 贴标签 | 在这个舵机上写“ID 2” | |

用固件改也可以：`dxl_set_id(1, 2)`，它会依次做第 2、3、4 步，返回 `DXL_OK` 就是成功。

## 4. 两个一起接上后的测试

| # | 发送 | 应该看到 | 不对时 |
|---|---|---|---|
| T1 | `FF FF FD 00 FE 03 00 01 31 42`（广播 ping） | 两个应答共 28 字节，ID 分别是 01 和 02 | 只有一个：另一个没电或线没插好；乱码：两个都还是 ID 1 |
| T2 | `FF FF FD 00 01 06 00 03 41 00 01 CC E6` | 舵机 A 的 LED 亮 | 亮的是 B：贴错标签 |
| T3 | `FF FF FD 00 02 06 00 03 41 00 01 FC E5` | 舵机 B 的 LED 亮 | |
| T4 | `FF FF FD 00 01 06 00 03 40 00 01 DB 66`，再发 `FF FF FD 00 02 06 00 03 40 00 01 EB 65` | 两个都打开扭矩，用手转不动 | |
| T5 | `FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 04 00 00 02 00 0C 00 00 13 0C` | 两个**同时**转，A 到 1024，B 到 3072；**没有应答**是正常的 | 只有一个动：查 T4 |
| T6 | `FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 0C 00 00 02 00 04 00 00 80 0C` | 两个同时反方向转回来 | |
| T7 | `FF FF FD 00 FE 09 00 82 84 00 04 00 01 02 CE FA`（Sync Read 位置） | 两个应答，各 15 字节，先 ID 1 后 ID 2 | 把收到的 HEX 用 `python tools/dxl_packet.py parse "…"` 解读 |
| T8 | 动作时量舵机 VDD 对 GND | 4.75 V 以上 | 电源不够，改用第 2 节的做法 B |

测完回到中间位置：`FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 08 00 00 02 00 08 00 00 68 4C`；关扭矩：`… 40 00 00 DE E6`（ID 1）和 `FF FF FD 00 02 06 00 03 40 00 00 EE E5`（ID 2）。

其他的包用工具生成：

```sh
python tools/dxl_packet.py sync-goal 1:2048 2:1000     # 两个舵机各自的目标
python tools/dxl_packet.py goal 2 3000                 # 只动 ID 2
python tools/dxl_packet.py parse "FF FF FD 00 …"       # 解读收到的应答
```

## 5. 软件

| 用法 | 文件 | 说明 |
|---|---|---|
| PC 手动发包 | `firmware/bridge/` + `tools/dxl_packet.py` | MCU 按包转发，自动切 DIR，舵机的应答原样回到 PC。第 3、4 节的测试都用这个 |
| 固件自己控制两个 | `firmware/dxl/dxl_example2.c` | ping 两个 → 轮流闪 LED → 两个同时反方向来回转，每次读回两个位置 |
| 以后接传感器 | `bridge_submit()` | 定时组一个 Sync Write 包放进同一个队列，见 `firmware/应用通信流程.md` 第 6 节 |

驱动新加的函数（`firmware/dxl/dxl.h`）：`dxl_sync_write`、`dxl_sync_read`、`dxl_sync_write_goal_position`、`dxl_sync_read_present_position`、`dxl_reboot`、`dxl_set_id`。Sync Read 时如果有一个舵机没回答，另一个的结果照样能读到，没回答的那个标为超时。

### 时间预算（两个舵机，57600）

| 动作 | 字节数 | 时间 |
|---|---|---|
| Sync Write 两个目标位置 | 24 | 约 4.2 ms |
| Sync Read 两个当前位置 | 16 + 2 × 15，加两次 Return Delay | 约 9.0 ms |
| 合计 | | 约 13 ms |

控制周期 20 ms（每秒 50 次）够用。要更快再把两个舵机都改成 1 Mbps（地址 8 写 3），Return Delay 改成 0。

## 6. 风险和对策

| 风险 | 现象 | 对策 |
|---|---|---|
| 两个都是 ID 1 | 两个同时回答，应答是乱码或 CRC 错 | 一定先单独改 ID，再串起来 |
| 电源不够 | 一动就通信中断，舵机 LED 闪（重启） | 电源 3 A 以上，舵机电源不走面包板 |
| 改 ID 时扭矩开着 | ID 写不进去，应答里有错误 | 先关扭矩（第 3 节第 2 步） |
| 两个波特率不同 | 只有一个能回答 | 用 `read 2 8 1` 读地址 8，两个要一样 |
| 线序 | 舵机不动、没有应答 | 舵机之间用 ROBOTIS 的 3P 线，不要自己改线序 |
