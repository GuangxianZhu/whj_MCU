# XC330 12V 接入方案：U2D2 + Power Hub → 自建 TTL 链路

2026-10-21 · 在线文档版（可评论）：https://claude.ai/artifact/AKvfTH3vZYcGBR34J9DmCg

## 目标与总路线

分两步，每步只换一个变量：**工作一（阶段 A）** 用官方链路 PC → U2D2 → Power Hub（下称 PHB）→ XC330，证明“新舵机 + 12V + PHB”本身没问题；**工作二（阶段 B）** 只把 U2D2 换成你的面包板（TXB0104 + 74LVC2G241 + M7C），PHB 继续只管 12V 供电。

为什么这样分：A 通过后，B 再出问题就只可能在面包板一侧或两边的接地，排查范围小一半。这是硬件调试的主流做法（先用已知好的工具建立基准）。

和现在的 XL330 接法相比，只有一处本质变化：

- 舵机电源从面包板 V1 的 5V 搬到 PHB 的 12V。面包板和舵机总线之间**只剩 DATA、GND 两根线**。
- 逻辑一侧不变：241、TXB 的 B 侧、R1 上拉仍用外部 5V；M7C 和 TXB 的 A 侧仍是 3.3V。XC330 的总线是 5V 逻辑（官方规格），和现在 241 输出的电平一致。

**电压提醒（公认结论，出自 ROBOTIS e-Manual）**：XC330-T181 / T288 的工作电压是 6.5–12.0V，推荐 11.1V。12V 正好是上限。ROBOTIS 自己配套的就是 12V 稳压电源，所以用 12V 适配器是常见做法；但上电前要量一下空载电压，明显高于 12V 的劣质适配器不要用。舵机内部的过压报警默认在 14.0V（地址 32），它不会替你挡住 12–14V 之间的长期超规格。

你的舵机型号决定 ping 应答里的型号字节：T181 = 1210（`BA 04`），T288 = 1220（`C4 04`）。XL330-M288 是 `B0 04`，所以以前检查表里写的 `B0 04` 换舵机后会变。

## 电压域与接线总图

三个电压域各管各的：12V 只在 PHB 和舵机之间；5V 和 3.3V 只在面包板上。两边只靠 DATA 和 GND 两根线相连。

```
工作一：U2D2 验证
  PC --USB-- U2D2 ==3P 线(GND/VDD/DATA 3 根)== PHB ==3P== XC330
                                                ^
                                           12V 适配器

工作二：换成 M7C（面包板部分按仓库，一根不改）
  PC --USB-- M7C(3.3V) -- TXB0104 -- 74LVC2G241(5V)
                                         |
                       第 4 列 DATA <----+---- 3P 线 3 号 DATA --+
                       第 2 列 GND  <--------- 3P 线 1 号 GND  --+-- PHB ==3P== XC330
                                     (不接) X- 3P 线 2 号 VDD 12V --+    ^
                                                                    12V 适配器
  面包板逻辑侧仍由外部 5V 和 M7C 的 3.3V 供电
```

（在线文档里有画好的版本。）

两行里 PHB 和 XC330 的位置不变，被换掉的只有：上面是 U2D2，下面是整块面包板电路。

## 工作一：U2D2 部分（阶段 A）

目标：用 Dynamixel Wizard 2.0 扫到 XC330，读到输入电压约 12V，LED 和转动都正常。这一步不碰面包板。

**准备**

- U2D2、U2D2 PHB、12V 适配器（DC 插头外径 5.5mm、内径 2.5mm，**中心正**，PHB 的 DC 口要求中心正）。
- 3P JST EH 线两根：U2D2 ↔ PHB 一根，PHB ↔ XC330 一根。PHB 的 TTL 口是 JST EH 3P，脚序 1 GND、2 VDD、3 DATA，和 XC330 一样。
- 面包板那套先和舵机断开。总线上同一时间只能有一个“主机”发包。

**步骤**（全程先断电接线，官方要求 PHB 通电时不要插拔舵机线）

1. 万用表量适配器空载电压和极性：中心为 +，约 12V。
2. PHB 电源开关拨到关。适配器只插 DC 口一个输入（官方要求同时只用一种电源输入）。
3. 3P 线：U2D2 的 TTL 口 → PHB 的一个 TTL 口；XC330 → PHB 的另一个 TTL 口。U2D2 的 USB 接电脑。
4. 打开 PHB 开关，XC330 的 LED 闪一下 = 供电正常。
5. Dynamixel Wizard 2.0：Options 里选 Protocol 2.0、波特率 57600、ID 0–252，Scan。应扫到 ID 1、型号 XC330-T181 或 T288。
6. 在控制表里看：Present Input Voltage（地址 144，单位 0.1V）约等于适配器电压；Hardware Error Status（地址 70）= 0。
7. LED（65）写 1 再写 0；Torque Enable（64）写 1，Goal Position（116）在 1024 和 3072 之间来回，看 Present Position（132）跟着变。最后 Torque 写回 0。
8. 关掉 Wizard 释放串口，用串口助手打开 U2D2 的 COM 口（57600 8N1），HEX 发 HANDOFF 里的 ping `FF FF FD 00 01 03 00 01 19 4E`。应答应该是 14 字节，型号字节是 `BA 04` 或 `C4 04`。

第 8 步的意义：它和以后 M7C 转发的是同一串字节。这一步通过，就说明“PC 串口助手发 HEX”这个用法在新舵机上成立，后面 M7C 部分出问题时可以排除数据包本身。

**不要在这一步改 ID 和波特率。** 保持出厂的 ID 1、57600，仓库里的固件和数据包都按这个写的，不用改。

**做完记下来（作为 M7C 部分的对照基准）**

- [ ] 型号号码、固件版本
- [ ] 静止时的 Present Input Voltage
- [ ] ping 应答的完整 14 字节
- [ ] （有逻辑分析仪的话）PHB 上 TTL 测试点的一段 ping 波形：空闲电平、一位约 17.4µs（57600 bps）

## 工作二：M7C 部分（阶段 B）

面包板上 M7C、TXB0104、74LVC2G241、R1–R3 的电路**完全按仓库 `docs/breadboard/README.md`，一根不改**。只换舵机那一端：原来插在舵机排针（2B/3B/4B）上的 XL330，换成一根从 PHB 来的线，而且这根线**只接 GND 和 DATA**。

**接法**

1. 断开 U2D2 和 PHB 之间的那根 3P 线（U2D2 不再在总线上）。XC330 仍插在 PHB 上。
2. 准备一根 JST EH 3P 转杜邦的线，插 PHB 空着的 TTL 口：
    - 1 号 GND → 舵机排针 2B（第 2 列，经 P2 到 V1 −）
    - 3 号 DATA → 舵机排针 4B（第 4 列，DATA 汇合点）
    - **2 号 VDD（12V）不接面包板**，线头包胶带单独放好
3. 面包板的外部 5V、M7C 的 USB 照旧。

为什么 VDD 不能插：第 3 列经 P3 接着 V1 + 的 5V。12V 一旦插进来，就和 5V 电源直接顶在一起，V1 + 会被抬高，241 的 VCC（绝对最大 6.5V）和 TXB 的 B 侧都扛不住。不插这根线，P3 和 C5 留着也无害，所以电路可以真的一根不改。

为什么 GND 必须接：DATA 的高低电平是相对地来说的。PHB 的地（12V 适配器的 −）和面包板的地（V1 −）不连，241 发出去的 5V 对舵机来说就是悬空的。这正是 2026-10-20 踩过的坑：地分开时出现回显、应答不稳。这次的地只走一条路：PHB → 3P 线 1 号 → 第 2 列 → P2 → V1 −。舵机的大电流从 PHB 直接回 12V 适配器，不经过面包板。

**上电前检查**（万用表，红笔/黑笔沿用仓库记号）

1. 全部断电，3P 线先不插面包板：蜂鸣档测第 4 列对第 2 列，不能响（DATA 没和地短路）。
2. 只开 PHB：量 3P 线 2 号对 1 号约 12V，3 号对 1 号**远低于 12V**（舵机空闲时 DATA 是高电平，几伏）。确认后关 PHB。
3. 3P 线按上面接好，按顺序上电：M7C 的 USB → 外部 5V → PHB 开关。
4. 红 V1 +，黑 V1 −：仍约 5V（没有被 12V 抬高）。红 4下，黑 V1 −：约 5V（DATA 空闲，R1 上拉）。
5. 断电顺序反过来：PHB → 5V → USB。

**通信测试**：按仓库的 `docs/breadboard/快速检查.md` 或 `firmware/dxl/dxl_bench.c` 走一遍，和以前一样。唯一不同的预期值：ping 应答的型号字节是 `BA 04`（T181）或 `C4 04`（T288），不是 `B0 04`。整串 14 字节应和工作一第 8 步记下的完全一样。

**另一个思路：U2D2 留着当“旁听”**（我的推测，未验证）。U2D2 不发包时应处于接收状态，不驱动总线，所以可以让它继续插在 PHB 上，电脑开串口助手只收不发，同时看到 M7C 发的包和舵机的应答，方便对照。风险：如果 U2D2 空闲时其实在驱动 DATA，就会和 241 抢总线。先按上面的主线做，通了以后想试再用逻辑分析仪确认 U2D2 空闲时不驱动。

## 固件和数据包：基本不用改

XC330 和 XL330 的出厂设置、协议和常用地址都一样（ID 1、57600、Protocol 2.0；Torque 64、LED 65、Goal Position 116、Present Position 132），所以 `firmware/dxl/`、`firmware/bridge/` 和 HANDOFF 里的数据包表**都能直接用**。仓库代码里型号号码只用来打印，没有地方拿它做判断。

| 项目 | XL330-M288（现在） | XC330（换后） |
| --- | --- | --- |
| 舵机电源 | 外部 5V，经面包板 | 12V，经 PHB |
| 型号号码 / ping 应答字节 | 1200 / `B0 04` | T181 1210 / `BA 04`；T288 1220 / `C4 04` |
| 打印文字里的型号说明 | “1200 = XL330-M288” | 文字过时，但不影响运行 |

新增一个有用的包：读输入电压（ID 1，地址 144，2 字节），由仓库的 `tools/dxl_packet.py read 1 144 2` 生成：

`FF FF FD 00 01 07 00 02 90 00 02 00 18 91`

应答的两个参数字节低位在前，乘 0.1 就是伏特，例如 `6E 00` = 110 = 11.0V。M7C 部分用它能确认“舵机确实吃到 12V”，而且不用碰万用表。

## 风险清单

按后果从重到轻排。前两条会烧东西，其余是通信不稳。

| 风险 | 后果 | 怎么防 | 依据 |
| --- | --- | --- | --- |
| 12V 进了面包板（VDD 插到第 3 列） | 5V 轨被抬高，241、TXB 损坏 | 3P 线 2 号不插面包板；上电后量 V1 + 仍约 5V | 241 绝对最大 6.5V（数据手册） |
| 适配器极性反、电压过高 | 舵机或 PHB 损坏 | 上电前量中心正、空载约 12V | XC330 规格 6.5–12.0V（e-Manual） |
| PHB 通电时插拔舵机线 | 可能损坏舵机或 PHB | 先关 PHB 开关再插拔 | ROBOTIS 官方警告 |
| U2D2 和 M7C 同时在总线上 | 两边同时发包，数据撞车 | 工作二开始前拔掉 U2D2 ↔ PHB 的线 | 半双工单线总线的基本规则 |
| PHB 地和 V1 − 没连 | 没有应答，或回显、CRC 错误 | 3P 线 1 号一定接第 2 列 | 仓库 HANDOFF 坑 2 |
| PHB 同时接两种电源输入 | 两个电源互相顶 | 只用 DC 口 | ROBOTIS 官方警告 |

## 预测题（先选再看答案）

**题 1**：工作二里，如果你把 3P 线的 2 号 VDD 也插进了第 3 列（P3 还在），然后打开 PHB。最先出问题的是哪个？

- A. XC330，因为 12V 超过它的规格
- B. 什么都不会发生，5V 电源会把电压“拉住”
- C. V1 + 被抬向 12V，241 和 TXB 的 B 侧超过耐压
- D. PHB 的保险丝熔断，保护了所有东西

**题 2**：只把 3P 线的 DATA 接到第 4 列，GND 忘了接。ping 最可能的结果是？

- A. 一切正常，因为两边各自有地
- B. 没有应答，或者应答时有时无、CRC 错误
- C. 舵机损坏

**答案**

题 1 选 **C**。12V 对 XC330 恰好在规格内，A 不对。大多数开关适配器只能“往外送电流”，不能“往回吸电流”，所以 5V 电源拉不住 12V，B 不对。PHB 的官方页面没有提到保险丝，不能指望它，D 不对。于是 V1 + 被抬高，241 的 VCC 绝对最大只有 6.5V，最先坏的是面包板上的芯片。

题 2 选 **B**。电平是两点之间的电压差。没有共地时，两边的“0V”可能经 USB、适配器等别的路径勉强连上，也可能完全不连，所以表现是时好时坏。这和仓库里 GND 分两条轨时的现象是同一个原理，只是更严重。
