# 接两个 XC330：一步一步

前提（2026-10-21 已完成）：一个 XC330-T288 已经通过 U2D2 和 M7C 面包板两条路都驱动成功，见 [`XC330_一步一步.md`](XC330_一步一步.md)。
这份是在它基础上加第二个舵机。原来的 [`两个舵机.md`](两个舵机.md) 是按 5V 的 XL330 写的，电源那部分不再适用；**数据包、Sync Write/Read 的原理和固件全部照用**。

## 一句话总结

先**单独**把新舵机改成 ID 2，再把两个舵机挂到 PHB 上；面包板一根不改，固件 `dxl_example2.c` 不用改。

## 和 XL330 的计划相比，变了什么

| 项目 | 原计划（XL330，5V） | 现在（XC330，12V + PHB） |
| --- | --- | --- |
| 电源 | 最担心的问题：两个堵转约 3A，要改接法让舵机电流不走面包板 | **已经解决**：舵机电流只走 PHB（最大 10A），不经过面包板 |
| 两个堵转电流 | 约 2.9A（5V） | 约 1.8A（12V 时每个 0.88A，e-Manual） |
| 外部 5V 电源 | 要 3A 以上 | 不变，只给逻辑，限流 100mA |
| 改 ID 的方法 | 只能用 M7C 发 HEX | 多一个更省事的：U2D2 + Dynamixel Wizard 点鼠标改 |
| ping 应答型号字节 | `B0 04` | `C4 04`（T288）；T181 是 `BA 04` |
| 面包板 / 固件 / 数据包 | — | 全部不变 |

12V 适配器：标签写的是 “12V AKA12050A1”，型号里的 “050” 我推测是 5.0A，**请看一眼标签上的电流（A）**。两个舵机最坏约 1.8A，2.5A 以上的适配器就够。

## 第 0 步：盘点（不通电）

1. **第二个舵机的型号**：背面标签是 XC330-**T**xxx（12V 版）吗？是 M 开头的就停下来，那是 5V 版。T181 和 T288 混用也可以，转一圈都是 4096，只是力气和速度不同。
2. **XC330 背面有几个插座**：两个插座的话，可以从舵机 A 再接一根线到舵机 B（菊花链）；两个插座在内部是直通的（这是 DYNAMIXEL 的通常设计，和 XL330 一样）。
3. **PHB 有几个空着的 3P 口**：现在已经占了两个（舵机 A、面包板）。
4. **3P 线**：需要再多一根（舵机 A → 舵机 B，或者 PHB → 舵机 B）。
5. 准备一张胶带和笔，等会儿给舵机写 “ID 1” “ID 2”。

接法从下面两种里选一种，电气上一样：

| 接法 | 怎么接 | 条件 |
| --- | --- | --- |
| **A：菊花链（推荐，最常见）** | PHB → 舵机 A → 舵机 B | 舵机 A 背面有两个插座 |
| B：都插 PHB | PHB → 舵机 A，PHB → 舵机 B | PHB 还有一个空 3P 口 |

为什么都能用：DYNAMIXEL 总线是一根线上挂多个设备（半双工多点总线）。三根线（GND、VDD、DATA）在所有插座之间都是并联的，舵机靠 **ID** 判断哪个包是发给自己的，不是靠插在哪个口。所以接线顺序无所谓，**ID 不能重复**才是关键。

## 第 1 步：给新舵机改 ID（总线上只能有它一个）

**先猜一下**：如果两个都是 ID 1 就一起接上，发 ping 1 会怎样？
A. ID 小的那个先回答　B. 两个同时回答，应答撞在一起变成乱码　C. 只有离 PHB 近的回答

答案是 **B**。两个舵机都认为包是发给自己的，又在同一时刻用同一根 DATA 线回答，信号叠在一起，收到的是乱码或 CRC 错误。所以必须先单独改 ID。

### 方法一（推荐）：U2D2 + Wizard，点鼠标就行

和工作一的接法一样，只是换成新舵机：

1. **PHB 开关关**。
2. 拔掉 PHB 上的**舵机 A**，拔掉 PHB 上**通往面包板的 3P 线**（总线上只能有一个主机发包）。
3. U2D2 → PHB 一根 3P 线（工作一用的那根），新舵机 → PHB。U2D2 的 USB 插电脑。
4. 开 PHB 开关，新舵机 LED 闪一下。
5. Wizard：Options 同工作一（Protocol 2.0、COMx、57600），Scan → 应扫到 `[ID:001] XC330-T288`。
6. 确认 **Torque** 是关的。控制表里找 **ID**（地址 7），把 1 改成 **2**，保存。
7. 再 Scan 一次：应该看到 `[ID:002]`。
8. 关 PHB 开关。在这个舵机上贴胶带写 **“ID 2”**，旧的那个写 **“ID 1”**。

### 方法二：M7C 面包板 + 串口助手发 HEX

不想换回 U2D2 时用。面包板、M7C 照工作二接好，**PHB 上只插新舵机**（拔掉舵机 A）。

| # | 发送 | 应该收到 |
| --- | --- | --- |
| 1 | ping 1：`FF FF FD 00 01 03 00 01 19 4E` | 14 字节，`… 55 00 C4 04 …` |
| 2 | 关扭矩：`FF FF FD 00 01 06 00 03 40 00 00 DE E6` | `FF FF FD 00 01 04 00 55 00 A1 0C` |
| 3 | ID 1 → 2：`FF FF FD 00 01 06 00 03 07 00 02 BD 63` | `FF FF FD 00 01 04 00 55 00 A1 0C`（还是 ID 1 回答，正常） |
| 4 | ping 2：`FF FF FD 00 02 03 00 01 19 72` | 14 字节，第 5 个字节是 `02` |

固件里也可以直接调 `dxl_set_id(1, 2)`，它会依次做第 2–4 步。

ID 存在 EEPROM 里，断电也不会丢。

## 第 2 步：两个一起接上

1. **PHB 开关关**（官方要求：通电时不要插拔舵机线）。
2. 用方法一的话：拔掉 U2D2 ↔ PHB 的线，把**通往面包板的 3P 线插回 PHB**。面包板那边还是只接 1 号 GND（第 2 列）和 3 号 DATA（第 4 列），2 号 VDD 包着胶带。
3. 按第 0 步选的接法 A 或 B 接上两个舵机。
4. 上电顺序和工作二一样：M7C 的 USB → 外部 5V → PHB 开关。
5. 两个舵机的 LED 都闪一下 = 都有电。

## 第 3 步：测试（串口助手，HEX）

所有包都由 `tools/dxl_packet.py` 生成。写入类的包，正常应答是 11 字节：ID 1 回 `FF FF FD 00 01 04 00 55 00 A1 0C`，ID 2 回 `FF FF FD 00 02 04 00 55 00 29 0C`。

| # | 做什么 | 发送 | 应该看到 | 不对时 |
| --- | --- | --- | --- | --- |
| T1 | 广播 ping | `FF FF FD 00 FE 03 00 01 31 42` | 两个应答连在一起共 28 字节，一个 ID `01`、一个 ID `02`，型号都是 `C4 04`（T181 是 `BA 04`） | 只有一个：另一个线没插好；乱码：两个都还是 ID 1，回第 1 步 |
| T2 | ID 1 的 LED 亮 | `FF FF FD 00 01 06 00 03 41 00 01 CC E6` | 贴着 “ID 1” 的舵机亮 | 亮的是另一个：标签贴反了 |
| T3 | ID 2 的 LED 亮 | `FF FF FD 00 02 06 00 03 41 00 01 FC E5` | 贴着 “ID 2” 的亮 | |
| T3' | 两个 LED 灭 | `FF FF FD 00 01 06 00 03 41 00 00 C9 66`、`FF FF FD 00 02 06 00 03 41 00 00 F9 65` | 都灭 | |
| T4 | 放慢速度（可选，建议做） | `FF FF FD 00 01 09 00 03 70 00 32 00 00 00 EE 81`、`FF FF FD 00 02 09 00 03 70 00 32 00 00 00 D2 21` | 各一个写入应答 | |
| T5 | 两个 Torque 开 | `FF FF FD 00 01 06 00 03 40 00 01 DB 66`、`FF FF FD 00 02 06 00 03 40 00 01 EB 65` | 两个都锁住，用手转不动 | **手离开舵盘** |
| T6 | 都回中间 2048 | `FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 08 00 00 02 00 08 00 00 68 4C` | 两个同时转到中间；**没有应答是正常的** | 只有一个动：查 T5 |
| T7 | 都转 +90°（3072） | `FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 0C 00 00 02 00 0C 00 00 23 8C` | 两个**同时**同方向转 90° | |
| T8 | 都回 2048 | 同 T6 | 同时转回来 | |
| T9 | 反方向：ID 1 → 3072，ID 2 → 1024 | `FF FF FD 00 FE 11 00 83 74 00 04 00 01 00 0C 00 00 02 00 04 00 00 80 0C` | 两个往相反方向各转 90° | |
| T10 | 读两个位置（Sync Read） | `FF FF FD 00 FE 09 00 82 84 00 04 00 01 02 CE FA` | 两个应答各 15 字节，先 ID 1 后 ID 2 | 用 `python tools/dxl_packet.py parse "…"` 解读 |
| T11 | 都回 2048，再关 Torque | 同 T6；然后 `FF FF FD 00 01 06 00 03 40 00 00 DE E6`、`FF FF FD 00 02 06 00 03 40 00 00 EE E5` | 回中间后松开 | |

T1 的一个小细节：广播 ping 时，舵机会错开时间回答，一般是 ID 1 在前。以每段应答的第 5 个字节为准，看它就知道是谁回答的。

**为什么 Sync Write（T6–T9）没有应答**：它是广播包（ID = FE），如果所有舵机都回答，就会撞在一起，所以协议规定广播写入一律不回答。“没应答”在这里是正常的；要确认有没有到位，用 T10 读回来。

### 固件版（不用手动发包）

`firmware/dxl/dxl_example2.c` 直接能用：ping 两个 → 轮流闪 LED → 两个反方向来回转并读回位置。它打印的型号是 1220（T288），文件注释里写的 “XL330” 不影响运行。

## 风险清单

| 风险 | 现象 | 对策 |
| --- | --- | --- |
| 两个都是 ID 1 就接上了 | 应答乱码、CRC 错误 | 先单独改 ID（第 1 步）；改错了就只留一个，重新改 |
| 改 ID 时 U2D2 和面包板同时在总线上 | 两个主机抢总线 | 第 1 步先拔掉 PHB 上通往面包板的线 |
| 改 ID 时 Torque 开着 | ID 写不进去，应答里有错误 | 先关 Torque |
| 通电时插拔舵机线 | 可能损坏舵机或 PHB | 先关 PHB 开关 |
| 舵机 A 和 B 波特率不同 | 只有一个回答 | 读 ID 2 的波特率：`FF FF FD 00 02 07 00 02 08 00 01 00 28 4B`，应答参数是 `01`（57600） |
| 新舵机是 5V 的 M 型号 | 接 12V 烧掉 | 第 0 步先看标签 |
| 两个同时用力时电压下降 | 一动就通信断、LED 闪（重启） | 读输入电压：ID 2 用 `FF FF FD 00 02 07 00 02 90 00 02 00 12 A1`；低于约 11V 查适配器电流 |
| 舵机转动夹手、撞到东西 | — | 舵机放稳，舵盘周围留出 90° 的空间，T5 之前手离开 |
