# 加一个 XC430-T240BB-T

> **2026-10-23 更新**：用户已完成本页确认（三个一起都没问题）。之后 XC430 留给手腕（目前仍是 ID 3，以后想改成 10 也可以）；手指用三个 XC330，用户的 ID 是 **0、1、2**，见 [`一根手指.md`](一根手指.md)。

在 [`两个XC330.md`](两个XC330.md) 的基础上，把一个 XC430-T240BB-T 挂到同一条总线上。
**结论：可以直接加。面包板不改，数据包格式和地址都一样，只要给它一个不重复的 ID（建议 3）。**

## 它和 XC330-T288 有什么不同

| 项目 | XC330-T288 | XC430-T240BB | 对我们的影响 |
| --- | --- | --- | --- |
| 工作电压 | 6.5–12.0V，推荐 11.1V | 6.5–14.8V，**推荐 12.0V** | 12V 对 XC430 正好是推荐值，余量比 XC330 大 |
| 12V 堵转电流 | 0.88A | **1.4A**（堵转扭矩 1.9 N·m） | 三个最坏约 3.2A，见“电源”一节 |
| 型号号码 / ping 应答字节 | 1220 / `C4 04` | **1080 / `38 04`** | 只影响你认它，不影响程序 |
| 出厂 ID / 波特率 / 协议 | 1 / 57600 / 2.0 | 一样 | 固件不用改 |
| 常用地址 | Torque 64、LED 65、Profile Velocity 112、Goal 116、Present 132、电压 144 | 一样 | HANDOFF 里的数据包都能用，只改 ID |
| 一圈 | 4096（90° = 1024） | 一样 | |
| 插头 | JST EH 3P | 附带 Robot Cable-X3P（JST-JST） | 和 XC330 的线通用（X3P 是 X 系列 3P 线，按我的理解就是 JST EH） |
| 欠压/过压报警默认 | 5.5V / 14.0V | 6.0V / 16.0V | 12V 都在范围内 |
| BB | — | 输出轴用金属滚珠轴承（不是塑料轴套），其余规格和普通 XC430 一样 | 抗轴向/侧向负载更好 |

数据来源：ROBOTIS e-Manual XC430-T240BB 页面（链接在文末）。

## 三种做法（选一种）

| 做法 | 内容 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A：先做完两个 XC330，再加 XC430 当 ID 3（推荐，最主流）** | 按 `两个XC330.md` 做到 T11 通过，再按本页加 XC430 | 每次只多一个变量，出问题马上知道是谁 | 要多等一步 |
| B：先单独试 XC430 | 像工作一那样：U2D2 + Wizard 只接 XC430，确认它能动，顺便改成 ID 3 | 马上能玩到新舵机；改 ID 和单独验证一次做完 | 不影响后面，基本没缺点，只是和两个 XC330 的进度分开了 |
| C：只用两个舵机：XC330（ID 1）+ XC430（ID 2） | 不加第三个，XC430 代替第二个 XC330 | 线最少 | 第二个 XC330 闲着；ID 要和 `两个XC330.md` 里的分配对清楚 |

**我建议 B → A 的顺序**：先单独试 XC430 并改成 ID 3（就是下面的第 1 步），再回去做两个 XC330，最后三个一起。这样改 ID 这件事是在“总线上只有它一个”的时候完成的，最安全。

## 电源：三个一起时要注意插线方式

**先猜一下**：三个都用菊花链（PHB → XC330 A → XC330 B → XC430）接，三个同时用力时，流过 PHB 和 XC330 A 之间那根 3P 线的电流大约是多少？
A. 1.4A，只有 XC430 那么多　B. 约 3.2A，三个加起来　C. 0.88A，只有 A 自己的

答案是 **B**。菊花链里，后面舵机的电流都要经过前面的线和插座。第一根线要扛 0.88 + 0.88 + 1.4 ≈ 3.2A。JST EH 插座每针的额定电流一般是 3A 左右（按 JST EH 规格，线粗时），已经顶到边了。

所以：

- **推荐：每个舵机都直接插 PHB 的口**（PHB 口不够时，至少让 XC430 单独插一个 PHB 口，两个 XC330 串在另一个口上，这样每根线最多约 1.8A）。
- 12V 适配器：三个最坏约 3.2A，加上余量需要 **4A 以上**。你的标签 “AKA12050A1” 如果是 5A 就够（请看标签上的 A 数确认）。PHB 最大 10A，没问题。
- 面包板一侧完全不变：外部 5V 只给逻辑，限流 100mA。
- 平时空转、不带负载时，电流远小于堵转电流；上面是最坏情况。

## 第 1 步：单独给 XC430 改 ID 3（总线上只有它一个）

和 `两个XC330.md` 第 1 步一样，只是新 ID 是 3。

**方法一（推荐）：U2D2 + Wizard**

1. PHB 开关关。拔掉 PHB 上所有舵机，拔掉通往面包板的 3P 线。
2. U2D2 → PHB，XC430 → PHB。U2D2 的 USB 插电脑。
3. **把 XC430 固定住**（用夹子或压在重物下）。它比 XC330 大一号，力气更大（12V 堵转扭矩 1.9 N·m），Torque 打开时会突然用力，没固定会跳起来。
4. 开 PHB 开关，XC430 的 LED 闪一下。
5. Wizard Scan（Protocol 2.0、COMx、57600）→ 应扫到 `[ID:001] XC430-T240BB`（或显示型号 1080）。
6. 看 Present Input Voltage（144）约 120（12.0V），Hardware Error Status（70）= 0。
7. 顺便试一下：LED、Torque 开、Goal Position 2048 → 3072 → 2048、Torque 关。
8. Torque 关着的状态下，把 **ID（地址 7）改成 3**，再 Scan 确认是 `[ID:003]`。
9. 关 PHB 开关，贴胶带写 “ID 3”。

**方法二：M7C 面包板 + 串口助手**（PHB 上只插 XC430 和通往面包板的线）

| # | 发送 | 应该收到 |
| --- | --- | --- |
| 1 | ping 1：`FF FF FD 00 01 03 00 01 19 4E` | 14 字节，`… 55 00 38 04 …`（型号 1080） |
| 2 | 关扭矩：`FF FF FD 00 01 06 00 03 40 00 00 DE E6` | `FF FF FD 00 01 04 00 55 00 A1 0C` |
| 3 | ID 1 → 3：`FF FF FD 00 01 06 00 03 07 00 03 B8 E3` | `FF FF FD 00 01 04 00 55 00 A1 0C` |
| 4 | ping 3：`FF FF FD 00 03 03 00 01 1A E6` | 14 字节，第 5 个字节是 `03`，型号 `38 04` |
| 5 | 读电压：`FF FF FD 00 03 07 00 02 90 00 02 00 14 B1` | 参数约 `78 00`（12.0V） |

## 第 2 步：三个一起测试

前提：两个 XC330 已经是 ID 1、ID 2（`两个XC330.md` 第 1 步）。按“电源”一节的方式接好，上电顺序照旧：M7C 的 USB → 外部 5V → PHB 开关。

ID 3 的写入类正常应答：`FF FF FD 00 03 04 00 55 00 52 8C`。

| # | 做什么 | 发送 | 应该看到 |
| --- | --- | --- | --- |
| U1 | 广播 ping | `FF FF FD 00 FE 03 00 01 31 42` | 三个应答共 42 字节：ID 01、02 型号 `C4 04`（T181 是 `BA 04`），ID 03 型号 `38 04` |
| U2 | ID 3 的 LED 亮 / 灭 | `FF FF FD 00 03 06 00 03 41 00 01 EF 64` / `FF FF FD 00 03 06 00 03 41 00 00 EA E4` | XC430 亮 / 灭 |
| U3 | 放慢 ID 3（ID 1、2 见 `两个XC330.md` T4） | `FF FF FD 00 03 09 00 03 70 00 32 00 00 00 C5 C1` | 写入应答 |
| U4 | 三个 Torque 开 | ID 1 `… 40 00 01 DB 66`、ID 2 `FF FF FD 00 02 06 00 03 40 00 01 EB 65`、ID 3 `FF FF FD 00 03 06 00 03 40 00 01 F8 E4` | 三个都锁住。**手离开** |
| U5 | 三个回中间 2048 | `FF FF FD 00 FE 16 00 83 74 00 04 00 01 00 08 00 00 02 00 08 00 00 03 00 08 00 00 78 4B` | 三个同时转；没有应答是正常的 |
| U6 | 三个都 +90° | `FF FF FD 00 FE 16 00 83 74 00 04 00 01 00 0C 00 00 02 00 0C 00 00 03 00 0C 00 00 35 75` | 三个同时转 90° |
| U7 | ID 2 反方向（1、3 → 3072，2 → 1024） | `FF FF FD 00 FE 16 00 83 74 00 04 00 01 00 0C 00 00 02 00 04 00 00 03 00 0C 00 00 05 F5` | 中间那个反着转 |
| U8 | 读三个位置 | `FF FF FD 00 FE 0A 00 82 84 00 04 00 01 02 03 2A 6C` | 三个应答各 15 字节，按 ID 1、2、3 的顺序 |
| U9 | 回中间，三个 Torque 关 | 同 U5；然后 ID 1 `… 40 00 00 DE E6`、ID 2 `FF FF FD 00 02 06 00 03 40 00 00 EE E5`、ID 3 `FF FF FD 00 03 06 00 03 40 00 00 FD 64` | 松开 |

收到的应答可以用 `python tools/dxl_packet.py parse "…"` 解读，现在它会直接打印型号名（XC330-T288、XC430-T240BB）。

### 固件版

`firmware/dxl/dxl_example3.c`：ping 三个并打印型号名 → 轮流闪 LED → 放慢速度 → 三个同时转（ID 2 反方向）并读回位置。在 `main()` 里把原来的 `dxl_example2_run()` 换成 `dxl_example3_run()` 就行（Keil 工程里要把这个文件加进去）。`dxl_example2.c` 没有动。

### 时间预算（三个舵机，57600）

Sync Write 三个约 29 字节 ≈ 5 ms；Sync Read 三个约 17 + 3 × 15 字节 + 三次 Return Delay（各 500µs）≈ 12.3 ms。合计约 17 ms，20 ms 的控制周期（每秒 50 次）还够用，但已经接近了。以后要更快，再把三个都改成 1 Mbps（地址 8 写 3）。

## 风险清单

| 风险 | 现象 | 对策 |
| --- | --- | --- |
| XC430 也是 ID 1 就接上了 | 应答乱码 | 先单独改成 ID 3 |
| XC430 没固定 | Torque 打开时跳起来、撞东西 | 夹住或压住；舵盘周围留出空间 |
| 三个串在一根菊花链上 | 第一根线和插座发热，同时用力时电压掉、舵机重启 | 每个直接插 PHB，至少 XC430 单独一个口 |
| 适配器电流不够 | 一起动时 LED 闪（重启）、通信断 | 适配器 4A 以上；用读电压的包（ID 3：`FF FF FD 00 03 07 00 02 90 00 02 00 14 B1`）看是否掉到 11V 以下 |
| 三个波特率不同 | 有一个不回答 | 读 ID 3 波特率：`FF FF FD 00 03 07 00 02 08 00 01 00 2E 5B`，应答参数是 `01` |
