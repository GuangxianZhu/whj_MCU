## 先猜一题

预紧以后，为什么**必须再标定一次**？

- A. 预紧会把 `calibration.yaml` 删掉
- B. 拧上线轮改变了绳长，“电机转多少 ↔ 关节转多少”的对应关系变了，旧的两端位置对不上了
- C. 预紧时舵机会断电，零点丢失
- D. 其实不用，标定一次就够

<details><summary>答案</summary>

**B**。标定记的是“关节顶到两端限位时，电机在哪个位置”（`motor_limits`）。拧紧上线轮以后，绳子短了一截：电机还在原来的位置时，关节已经被多拉过去一点，所以两端位置整体偏移了。A 不对，`tension.py` 不碰 `calibration.yaml`【源码】。C 不对，预紧时一直通电。
</details>

## ① 预紧（`tension.py`，菜单 5）

### 它到底做了什么【源码：`maintenance/tensioning.py`】

| 阶段 | 做什么 | 为什么 |
|---|---|---|
| 1. 卷绳 winding | **16 个手指电机**（手腕不动）以 300 mA 先往一个方向转、再往反方向转，各自转到 1 秒不动为止，每个方向最多 20 秒 | 把绳里的松弛赶到一边，让绳在线轮上贴好 |
| 2. 慢放 ramp | 1 秒内电流从 300 mA 降到 0，再关扭矩 | 防止绳子“啪”地弹回去 |
| 3. 预拉 15° | 手指电机以 10°/s 逆时针慢慢转 15°（300 mA 上限），停稳后原地锁住 | 给下线轮先加点力，棘轮拧的时候更容易吃进松弛 |
| 4. 保持 holding | 锁住不动，**电流上限提到每个舵机自己的 Current Limit（地址 38，远大于 300 mA）** | 你拧棘轮时会推着电机走；300 mA 顶不住会被拧动。只有被推离目标位置时才出力 |
| 5. Ctrl+C | 恢复 300 mA 和原控制模式，关扭矩 | |

### 操作

```bat
:: 菜单 5，或者官方命令：
uv run python scripts\tension.py <你的 config.yaml>
```

1. 终端显示 `Holding motors for manual tensioning` 后再动手。
2. 用棘轮工具把**每个电机的上线轮顺时针**拧。能听到或感觉到“咔哒”，说明棘轮咬住了。【官方】
3. **拧到绳子“摸起来紧”就停**，留一点点余量是允许的。官方原话是“很容易拧过头，过紧会影响性能”。【官方】
4. 全部拧完，按 Ctrl+C。

### 一定要注意

- **第 4 阶段电流上限很大。** 拧得越紧，电机顶回来的力越大。中指 ABD 的结就是被大力拉穿孔的（`docs/遇到问题/中指ABD腱绳脱出.md`）。所以**宁松勿紧**：松了可以下一轮再补，拉穿了就得拆。
- **ABD 绳（外展）要特别轻，中指 ABD（ID 6）刚修好，尤其要轻。** v2.1 专门把 ABD 的标定电流压在 300 mA，而 MCP/PIP 用 500 mA。【源码】ABD 的绳对拉力更敏感【推测】。
- 听到“嘎嘣”、绳子明显在动、或者有关节被拉歪：先按 Ctrl+C，再找原因。

## 怎么判断“预紧 + 标定”收敛了

官方只说“直到标定后不再出现松弛”。下面这个办法能用数字看。

**原理**：每次标定，`calibration.yaml` 里都会记 `motor_travel_measured`，也就是每个关节从一端限位到另一端，电机转了多少度。v2.0 也会记，只是 orca_core 不拿它做检查。【源码】

- 绳**太紧或卡住**：电机还没把关节推到限位就顶不动了，测到的行程**偏短**。
- 绳**松**：电机要先空转一段收绳，测到的行程**偏长**。

`compare_travel.py` 的输出怎么看：

| 列 | 意思 | 怎么判断 |
|---|---|---|
| `delta` | 和上一轮比，变了多少 | 每轮越来越小，就是在收敛。官方没给阈值，我建议看趋势 |
| `v2.1ref` | 官方 v2.1 的基准行程 | **只作参考**，v2.0 的几何可能不一样 |
| `vs sib` | 和同类关节比（4 根手指的 MCP 之间比，PIP、ABD 同理），先按基准做了归一化 | 低于 75% 会标“太紧/卡住?”，高于 125% 会标“松/打滑?”。25% 来自 orca_core 自己的 `calibration_travel_margin` 默认值 |

一般 2–3 轮就够了。被标记的关节，下一轮只针对它调（太紧就松一格棘轮，偏长就补拧）。

## ④ 换成 KM1M7C

### 原理：为什么能直接换

- orca_core 只看见“一个 COM 口”，不关心后面是 FTDI（U2D2）还是 KM1M7C。【源码】
- `calibration.yaml` 记的是舵机自己的绝对位置，和转接器无关。只要腱绳没动，**换了转接器不用重新标定**。【源码 + 推测】

### 坑 1：config 里必须写死 `baudrate: 57600`【计算 + 源码】

- KM1M7C 的 USB 虚拟串口**不管电脑设多少波特率**，舵机那边永远是固件定的 57600。
- orca_core 自动探测时先试 1 Mbps。通过 KM1M7C，“1M 下 ping”也能通，于是它会**以为是 1M**。
- DynamixelSDK 等应答的超时 = 字节数 × 每字节时间 + 34 ms：
  - 按 1M 算：一次全读的超时约 **38 ms**；
  - 实际按 57600 传：要 **约 62 ms**；
  - 结果：每次都超时，读出来的全是旧数据。
- 写死 57600 以后，超时约 96 ms，够用。`Start-ORCA.bat` 生成的 config 已经写死了；**用官方 config 直接接 KM1M7C 会踩这个坑**。

### 坑 2：Return Delay 和 TXEN 时序【源码 + 推测】

- 舵机收完指令以后，等 Return Delay Time 再回答：出厂值 500 µs；如果用过 `configure_motor_chain.py`，是 **20 µs**。【源码】
- 你的固件必须在**最后一个字节的停止位发完以后**、这段时间以内，把 TXEN 切回 0：
  - 用 **TC（发送完成）** 标志：对。
  - 用 TXE / 缓冲区空：会早一个字节切，最后一个 CRC 字节被截断，舵机不回答。
  - 用固定延时：太长的话，应答开头的字节会丢。
- 第 ③ 步 B 菜单会打印每个舵机的值。如果是 20 µs 而桥接不稳，两个办法：
  - 改固件，用 TC 标志；
  - 用 Wizard 把地址 9 调回 250（= 500 µs）。代价是每次全读多 17 × 0.5 ≈ 8.5 ms。

| 做法 | 怎么做 | 取舍 |

| **A（推荐）现在就改用 `my_hand` config** | 菜单 C 填 **U2D2 的 COM**、57600、版本 2；把现在的 `calibration.yaml` 复制到 `tools\orca\my_hand\`；用它做 ①～③ | U2D2 和 KM1M7C 用同一份 config，换的时候**只改 COM 口一个变量**，对比数据才有意义 |
| B 先用官方路径，换的时候再搬 | 换 KM1M7C 时菜单 C 填 KM1M7C 的 COM，再复制 `calibration.yaml` | 现在少一步；但对比 U2D2 和 KM1M7C 时，config 也不一样了 |

`calibration.yaml` 在哪：用官方命令时，在 `orca_core\orca_core\models\v2\orcahand-left\calibration.yaml`（就在 config.yaml 旁边）。菜单 C 重新生成 config 时，**不会**覆盖 `my_hand` 里已有的 `calibration.yaml`。

### 接线

1. 12V Power Hub 供电**保持不变**。
2. 把 U2D2 的 USB 线和 3P 线**都拔掉**。总线上同时挂两个主机会打架。
3. PHB 来的 3P 线只接面包板的 **GND（第 2 列）和 DATA（第 4 列）**，**12V 的 VDD 不接面包板**（和 `docs/XC330_一步一步.md` 工作二一样）。
4. KM1M7C 的 USB 插电脑，烧好你的透传固件（UART5 ⇄ UART2，舵机侧 57600）。
5. 关掉串口助手和 Dynamixel Wizard。Windows 的 COM 口只能一个程序用。

### 出问题怎么查

| 现象 | 最可能的原因 | 先查 |
|---|---|---|
| K1/K2 一个都找不到 | COM 口不对；固件舵机侧不是 57600；TXEN 极性反了；没共地 | 用串口助手发 ping `FF FF FD 00 01 03 00 01 19 4E`（ID 1） |
| 能 ping 通，但全读失败或很慢 | config 没写死 57600（坑 1）；固件缓冲区放不下一整包应答（约 360 字节） | 看 config 开头的 `baudrate:` 行；看固件的缓冲区大小 |
| 时好时坏，个别舵机掉线 | TXEN 切回太晚或太早（坑 2） | 看 B 菜单打印的 Return Delay；用逻辑分析仪看 DIR 和 DATA |
| `PermissionError: Access is denied` | COM 口被别的程序占着 | 关掉串口助手、Wizard、另一个终端 |
| 动作比 U2D2 卡 | 两边都是 57600，理论上应该差不多【推测】 | 对比 K1 和 ③ 的数字 |

## ⑤（可选）提速到 1 Mbps

KM1M7C 稳定以后再考虑。**一次只改一个变量**：

1. 用 U2D2：`configure_motor_chain.py <config> --baudrate 1000000` 改 17 个舵机。
2. 固件舵机侧改成 1M，config 的 `baudrate` 改成 1000000。
3. 重做 K1。全读应该降到几毫秒（每秒约 200 次）。【计算】

改到一半出错的话，舵机会停在新波特率上。要先能用 U2D2 + Wizard 救回来，再动手。
