# ping 没有应答怎么查

现象：PC 发了 ping，收不到 XL330 的应答。

按信号走的顺序一段一段查：供电 → DIR → 发送通路 → 接收通路 → 软件。前 5 步只用万用表。孔位编号和 [接线清单](README.md#接线清单) 一致，“槽上方”指 G–L，“槽下方”指 A–F。

## 0. 先确认是怎么发的 ping

| 方式 | 谁负责切 DIR |
|---|---|
| A. PC 串口助手发给 MCU，MCU 固件转发给舵机 | 转发固件必须自己切 DIR（见第 3 步） |
| B. 用 `firmware/dxl/dxl_example.c`，MCU 自己发 | 驱动已经切了，只要 `dxl_port_*` 五个函数写对 |
| C. USB 转串口线直接接 TXB，不经过 MCU | 没人切 DIR，241 永远在接收，一定收不到。这种接法不行 |

## 1. 舵机有没有电

- 舵机上电时背面 LED 会闪一下。不闪就是没电，后面不用查。
- 测第 3 列对第 2 列（槽下方）：约 5V。

## 2. 静态电压（上电，不发数据）

| 测哪里（对 GND） | 应该是 | 不对时查 |
|---|---|---|
| 14E（TXB LV） | 3.3V | M1 |
| 14G（TXB HV） | 5V | P7、P4、P5 |
| 6G（241 第 8 脚 VCC） | 5V | P4 |
| 9F（241 第 4 脚 GND）对 V1 − | 0Ω（蜂鸣档，断电测） | P6、P8、P1 |
| 第 4 列槽下方（DATA） | 约 5V（R1 上拉） | R1、P11 |
| 15B（DIR，不发送时） | 0V | R3 |

## 3. DIR 有没有切换（最常见的原因）

发送一个包的顺序必须是：

1. DIR = 1
2. 写完所有字节
3. 等 UART 的“发送完成”（TC）标志，不是“发送缓冲空”（TXE）
4. DIR = 0
5. 接收应答

如果是方式 A，转发固件只是把 PC 来的字节原样写给 UART、没有做 1 和 4，ping 就送不到舵机。如果 3 用了 TXE，最后一两个字节会被截掉，舵机会因为 CRC 不对而不应答。

**测试**：固件里把 DIR 固定拉高，测：

| 测哪里 | 应该是 |
|---|---|
| 15B（A1） | 3.3V |
| 15G（B1） | 5V |
| 7G（241 第 7 脚 2OE） | 5V |
| 第 6 列槽下方（241 第 1 脚 1OE） | 5V |

## 4. 发送通路（DIR 固定为 1）

把 MCU 的 TX 脚临时当 GPIO 用，测第 4 列槽下方（DATA）：

- TX 输出高 → 约 5V
- TX 输出低 → 约 0V

不跟着变时，沿路逐点测，找出哪一段断了：

17B（A3，3.3V）→ 17G（B3，5V）→ 9G（241 第 5 脚 2A）→ 第 8 列槽下方（241 第 3 脚 2Y）→ 第 4 列槽下方（DATA）

## 5. 接收通路（DIR = 0）

用一根线把第 4 列槽下方（DATA）临时接到 GND（DATA 只有 10k 上拉，接地没有危险）：

| 测哪里 | 接地时 | 断开后 |
|---|---|---|
| 第 7 列槽下方（241 第 2 脚 1A） | 0V | 5V |
| 8G（241 第 6 脚 1Y） | 0V | 5V |
| 16G（B2） | 0V | 5V |
| 16B（A2，接 MCU RX） | 0V | 3.3V |

## 6. 软件和数据

- 串口：**57600 bps，8 位数据，无校验，1 位停止位**。
- 按 **HEX** 发：`FF FF FD 00 01 03 00 01 19 4E`。串口助手默认往往是“文本”模式，发出去的是 ASCII 字符，舵机不会应答。
- 先确认 PC ↔ MCU 这一段是通的：拔掉舵机，让 MCU 把收到的字节原样回给 PC，看能不能收到。
- MCU 的 TX 接 17B（A3），RX 接 16B（A2），别接反。
- 舵机如果被别人改过 ID、波特率或协议版本，用 DYNAMIXEL Wizard 2.0 扫描所有波特率，或者恢复出厂设置（ID 1、57600、Protocol 2.0）。

## 7. 有示波器或逻辑分析仪时

同时看三路：MCU TX（17B）、DIR（15B）、DATA（第 4 列）。

- 发送时 DIR 应该先变高，包出完之后才变低。
- DATA 上应该先看到 10 个字节的 ping，大约 0.5ms 后再出现舵机的应答（XL330 默认 Return Delay Time 为 500µs）。
- 如果 DATA 上有 ping 但没有应答 → 查第 6 步（波特率、ID、包内容）。
- 如果 DATA 上有应答但 PC 收不到 → 查第 5 步和 MCU 的接收、转发代码。
