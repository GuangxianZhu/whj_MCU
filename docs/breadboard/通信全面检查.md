# XL330 通信全面检查

所有接线都已完成，但通信有问题时，从头逐项测一遍。每一项都写了测哪里、应该是多少，以及不对时最可能的原因。 交互版（填数自动判断）见 [`通信全面检查.html`](通信全面检查.html)，下载后用浏览器打开。

## 记号

- **6下**：第 6 列槽下方（A–F 行）的任意一个孔或针；**6上**：第 6 列槽上方（G–L 行）。
- **V1 +、V1 −、V3 −**：电源轨。V1 是外部 5V 和 GND，V3 − 是 MCU 的 GND。
- **模式 A/B/C**：为了测试临时改的固件状态。A：DIR = 0，UART 空闲；B：DIR = 1，TX 引脚当 GPIO 输出 1；C：DIR = 1，TX 输出 0。
- 按顺序测，遇到第一个不对的项先修好，再往下测。后面的项默认前面都已通过。

## 1. 断电 · 目视

拔掉 USB 和外部 5V。对照接线清单看一遍，每项确认后点“是”。

| # | 测量 | 应该 | 不对时 |
|---|---|---|---|

## 4. 发送通路

固件进入**模式 B**：DIR 输出 1，TX 引脚临时改成 GPIO 输出 1。测完前四项后改为**模式 C**：DIR 仍为 1，TX 输出 0。DATA 被拉低一会儿不会伤到舵机。

| # | 测量 | 应该 | 不对时 |
|---|---|---|---|
| 4.1 | 红 15下（A1），黑 V3− | 3–3.6 V | DIR 引脚没有输出 1。 |
| 4.2 | 红 15上（B1），黑 V3− | 4.5–5.25 V | 约 3.5V 时 R3 插成了 10k；更低时查 S4、S7 有没有接到地。 |
| 4.3 | 红 7上（2OE），黑 V3− | 4.5–5.25 V | S4 接触不良。 |
| 4.4 | 红 6下（1OE），黑 V3− | 4.5–5.25 V | S7 接触不良。 |
| 4.5 | 红 模式 C：17下（A3），黑 V3− | 0–0.3 V | TX 引脚没有输出 0：引脚选错或复用没改成 GPIO。 |
| 4.6 | 红 模式 C：17上（B3），黑 V3− | 0–0.3 V | A3 是低但 B3 不低：TXB 第 3 通道有问题。 |
| 4.7 | 红 模式 C：9上（241 2A），黑 V3− | 0–0.3 V | S6 断开。 |
| 4.8 | 红 模式 C：4下（DATA），黑 V3− | 0–0.4 V | 2A 是低但 DATA 不低：2OE 没打开（查 4.3），S8 断开，或 241 方向插反。 |
| 4.9 | 红 模式 C：16下（A2 → MCU RX），黑 V3− | 3–3.6 V | 发送时 RX 也变低，说明 1Y 没关：1OE 没被拉高（查 4.4、S7），MCU 会收到自己发的数据。 |

## 5. 接收通路

固件回到**模式 A**（DIR = 0，UART 空闲）。拿一根线，一端插 V1 −，另一端插 4下 的空孔，让 DATA 接地。DATA 上只有 10k 上拉，接地是安全的。

| # | 测量 | 应该 | 不对时 |
|---|---|---|---|
| 5.1 | 红 DATA 接地时：8上（1Y），黑 V3− | 0–0.4 V | 1Y 不跟随 DATA：S9 断开，或 1OE 不是低（查 3.12）。 |
| 5.2 | 红 DATA 接地时：16上（B2），黑 V3− | 0–0.4 V | S5 断开。 |
| 5.3 | 红 DATA 接地时：16下（A2 → MCU RX），黑 V3− | 0–0.3 V | TXB 第 2 通道有问题。 |
| 5.4 | 红 拔掉接地线后：16下，黑 V3− | 3–3.6 V | 拔掉后不回高：B2 没有上拉，查 R2。 |
| 5.5 | 如果固件能打印收到的字节：DATA 接地再拔开时，MCU 收到 0x00 或报帧错误 | 是 | 电平到了 RX 针但 UART 没收到：RX 引脚复用没设对，或用错了 UART 通道。 |

## 6. 固件和数据

电平都正确以后，回到正常程序再查这些。

| # | 测量 | 应该 | 不对时 |
|---|---|---|---|
| 6.1 | UART 是 57600 bps、8 位数据、无校验、1 位停止位 | 是 | XL330 出厂是 57600。波特率不对，舵机会把数据当成乱码丢掉。 |
| 6.2 | 用的 UART 通道和引脚复用，正好是接到 16下、17下 的那两只针 | 是 | 很多 MCU 一个 UART 有多组可选引脚，选错了数据发不到线上。 |
| 6.3 | DIR 引脚是推挽输出，上电初始化时先写 0 | 是 | 开漏或没初始化时 DIR 不受控。 |
| 6.4 | 发送顺序：DIR = 1 → 写完所有字节 → 等“发送完成”（TC）→ DIR = 0 → 接收 | 是 | 用“发送缓冲空”（TXE）会提前切 DIR，最后一两个字节被截掉，舵机因 CRC 错误不应答。 |
| 6.5 | 发送前清空接收缓冲，接收超时至少 20ms | 是 | 应答共 14 字节，57600 下约 2.4ms，加上 0.5ms 的 Return Delay。超时太短会提前放弃。 |
| 6.6 | 按 HEX 发 ping：FF FF FD 00 01 03 00 01 19 4E | 是 | 串口助手默认是文本模式，发出去的是 ASCII 字符。PC 经 MCU 转发时，转发程序也必须按 6.4 切换 DIR。 |
| 6.7 | 只测发送：发 FF FF FD 00 01 06 00 03 41 00 01 CC E6，舵机 LED 亮；发 FF FF FD 00 01 06 00 03 41 00 00 C9 66，LED 灭 | 是 | 这条不需要接收。LED 能亮说明发送通路、波特率和 ID 都没问题，问题在接收（第 5 节和 6.2）；LED 不亮就查第 4 节、6.1、6.4，或用 6.8 找 ID。 |
| 6.8 | 广播 ping：FF FF FD 00 FE 03 00 01 31 42 能收到应答 | 是 | 不知道舵机 ID 时用这条，所有 ID 都会应答。再不行，就依次换 9600、57600、115200、1M、2M、3M、4M 各发一次，排除波特率被改过的情况。 |

## 正常的 ping 应答

`FF FF FD 00 01 07 00 55 00 B0 04 xx CRC_L CRC_H`，一共 14 字节。
`55` 表示这是应答包，`00` 表示没有错误，`B0 04` 是型号 1200（XL330-M288；M077 是 `A6 04`），`xx` 是固件版本，所以最后两个 CRC 字节因舵机而异。
