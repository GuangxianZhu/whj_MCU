# XL330 分级检查

接线全部完成但通信有问题时，按这份表从头测。顺序是一级一级往上加：先只测 MCU，再带上 TXB0104，再加 74LVC2G241，最后接舵机。每一级都用短线做一个回环，自己发、自己收，所以不需要舵机也能确认这一级是好的。前一级全部通过再进下一级，出问题时就能锁定在新加的那一块。

交互版（填数自动判断）见 [`分级检查.html`](分级检查.html)，下载后用浏览器打开。

## 记号和测试程序

- **6下**：第 6 列槽下方（A–F 行）的任意一个孔或针；**6上**：第 6 列槽上方（G–L 行）。
- **V1 +、V1 −**：外部 5V 和 GND；**V3 −**：MCU 的 GND。电压项黑表笔默认放 V3 −。
- “状态”一栏写的是测这一项时电路和固件的状态：断电、上电，或下面几种测试程序。
- **模式 A**：DIR 输出 0，UART 初始化好但不发送。
- **模式 B**：DIR 输出 1，TX 引脚临时改成 GPIO 输出 1。
- **模式 C**：DIR 输出 1，TX 引脚当 GPIO 输出 0。
- **程序 L**：回环程序。每 0.5 秒按正常流程（DIR = 1 → 发 10 字节 → 等发送完成 → DIR = 0）发一次 FF FF FD 00 01 03 00 01 19 4E；接收一直开着（用中断收，发送时也收），收到的字节原样打印到 PC。

| 4.10 | 正常程序 | 依次用 9600、57600、115200、1M、2M、3M、4M 各发一次广播 ping，有一个能收到应答 | 是 | 找出舵机现在的波特率。 | 都不行：舵机可能被设成了别的协议或已损坏，需要用 U2D2 和 DYNAMIXEL Wizard 恢复出厂设置。 |
| 4.11 | 正常程序 | PC 经 MCU 转发时：串口助手用 HEX 模式发送，转发程序也按 DIR = 1 → 发送 → 等 TC → DIR = 0 切换 | 是 | 排除 PC 侧发送方式的问题。 | 文本模式发出去的是 ASCII 字符；转发程序不切 DIR，包就到不了总线。 |

## 正常的 ping 应答

`FF FF FD 00 01 07 00 55 00 B0 04 xx CRC_L CRC_H`，一共 14 字节。
`55` 表示这是应答包，`00` 表示没有错误，`B0 04` 是型号 1200（XL330-M288；M077 是 `A6 04`），`xx` 是固件版本，所以最后两个 CRC 字节因舵机而异。

## 按现象找方向

| 现象 | 先看 |
|---|---|
| LED 不亮（4.7），ping 也没有应答 | 第 3 节都过了的话看 4.9、4.10；没做第 3 节就从 3.24 开始 |
| LED 能亮，但 ping 没有应答 | 3.26、3.29（接收通路和 DIR 时机）、4.8 |
| 收到的是自己刚发的 10 个字节 | 3.25、3.28：1OE 没被拉高，查 S7 |
| 偶尔有应答，经常 CRC 错误 | 3.29（只收到一部分就是 TC/TXE 的问题）、0.12（地没连通）、0.6、0.7（电阻阻值） |
| 舵机一转就断 | 外部电源电流不够，C4 没接好 |
