# 故障排查：TTL 电路的 5V 碰到了电源板的 12V

> **以 `明天照着做.md` 为准。** 后来确认电路已经焊在万能板上（芯片插在排母上、有备用件），这份里按面包板孔位写的测法用不上了。这份只留作事故分析的记录。

日期：2026-11-16。情况（用户口述）：一块 TTL 电路的 5V 线和电源板的 12V 连在了一起，当时 12V 和 USB 都通着；只有一块电路接错；之后 M7C 插电脑还能看到 COM 口，但手控制不了。5V 的来源不确定。

`<whj_MCU>` 指本仓库的文件夹。命令在 orca_core 文件夹里运行。

## 11-16 晚补充：已经排除的和事故的真正路径

用户确认：**舵机用 U2D2 测过，能控制；MCU 也确认过没问题。** 所以下面第 1、4 步可以跳过，剩下的嫌疑只有 TXB0104 和 74LVC2G241。

事故路径：舵机 3 针线**中间那根（2 号 VDD，12V）插到了面包板上**。面包板第 3 列经跳线 **P3** 接着 5V 轨（这是早先舵机用 5V 供电时留下的），所以 12V 顺着 P3 进了 5V 轨，加到了 241 的 VCC 和 TXB 的 HV 上。`docs/XC330_12V接入方案.md` 里写过这根线不能插。

**先做一件事：把两块电路上的 P3 都拔掉。** 现在舵机由电源板供电，第 3 列不需要再连 5V。拔掉以后，即使中间那根线再插错，12V 也进不了 5V 轨。

**怎么测 TXB 和 241**：仓库里已经有现成的步骤，`docs/breadboard/分级检查.md`（同目录有可填数的 `分级检查.html`）。只用万用表和几根短线，不需要测试固件：

| 测谁 | 看哪一节 | 做哪几项 |
|---|---|---|
| TXB0104 | 第 2 节 | 2.9–2.11（两路电源和 OE），2.12–2.15（跳线 A/B/C，看 B1、B3 跟不跟） |
| 74LVC2G241 | 第 3 节 | 3.13–3.17（短路和电源），3.18–3.26（跳线 A/B/C，看 DATA 和 MCU RX 那一脚） |

带“程序 L”的两项（2.16、3.28、3.29）要烧测试固件，可以不做，用最后的真机检查代替。

注意那份文档开头的“跳线注意”：接跳线前先把 S1、S3 从 15B、17B 拔出来；A 侧只能接 3.3V 或地，不能碰 5V。

判断：
- 哪一节有一项不对，就是那一片坏了，换那一片。TXB 是 Adafruit 1875 模块，整块换；241 在转接板上，连转接板一起换。
- 两节都对，再接上舵机跑 `check_buses.py` 和 `bus_timing.py`。应答正常、失败次数为 0，这块电路就可以继续用。
- 万用表测的是静态电平。受过过压的芯片在 1 Mbps 下出错的情况，只有接上舵机跑 `bus_timing.py` 才看得出来，所以这一步不能省。备用件还是建议订上。

## 结论

| 部件 | 判断 | 依据 |
|---|---|---|
| 74LVC2G241（那块电路上的） | **按坏了处理，换掉** | 数据手册：VCC 绝对最大 6.5V，12V 接近两倍 |
| TXB0104（那块电路上的） | **按坏了处理，换掉** | 数据手册：B 侧电源范围 1.65–5.5V |
| 外部 5V 电源 | 要量 | 它的输出端被 12V 顶过 |
| M7C（那块） | 多半没事，要验证 | COM 口还在，说明 USB 部分活着；它用的是 3.3V，不在 5V 轨上。但 TXB 坏的瞬间高压可能窜到它的串口脚 |
| 那根手指的 3 个舵机 | 要验证 | 241 的输出直接连着舵机的 DATA，241 的电源变成 12V 时 DATA 上可能出现过高于 5V 的电压 |
| 另一块 TTL 电路 | **先确认它的 5V 是不是同一个电源** | 两块电路如果共用一个 5V，那它也被 12V 顶过，同样要查 |

## 第 0 步：先别通电

1. 关 12V，拔 USB，断开外部 5V。
2. 把接错的那根线拆掉。
3. 把坏的那块 TTL 电路和舵机之间的 DATA 线拔开，修好之前不要再接到舵机上。
4. 看一眼两块电路的 5V 是不是接在同一个电源上。是的话，下面对“好的那块”也要先做第 3 步的测量，再拿它当参照。

## 第 1 步：舵机坏没坏（用好的那块电路当参照，5 分钟）

思路：把可疑的东西接到确定是好的东西上，看通不通。

1. 把**可疑手指**的 DATA 接到**好的那块** TTL 电路上（先把好电路原来带的那根手指拔开）。GND 照旧共地，12V 只给舵机。
2. 通电，只读检查（把 COM5 换成好板的 COM 号）：

```bat
uv run python <whj_MCU>\tools\orca\multibus\check_buses.py --ports COM5
```

| 结果 | 说明 |
|---|---|
| 可疑手指的 3 个 ID 都回答 | 舵机没坏，问题只在那块 TTL 电路上 |
| 一个都不回答 | 再把好电路接回它原来的手指跑一次。原来的手指能回答，说明可疑手指的舵机通信坏了；也不回答，说明好电路也出了问题，回第 0 步第 4 条 |
| 只有一两个回答 | 没回答的那个舵机坏了，或者手指内部的串联线松了 |

手边有 U2D2 的话，用它代替“好的那块电路”做这一步更干净：U2D2 只接 GND 和 DATA。

## 第 2 步：外部 5V 电源坏没坏（1 分钟）

把 5V 电源从电路上断开，单独通电，量输出：4.8–5.2V 算正常。不在这个范围就换电源。

## 第 3 步：坏的那块电路（不接舵机）

只接 USB 和 5V，不接舵机，量：

| 量哪里 | 正常值 | 不正常说明 |
|---|---|---|
| 5V 轨 | 约 5V | 被拉低：有芯片内部短路 |
| 3.3V（TXB 的 A 侧电源） | 约 3.3V | 异常：M7C 板或 TXB 有问题 |
| DATA（空闲时） | 约 5V | 被拉低或者不到 4V：241 坏了 |
| 用手指碰 241、TXB | 不烫 | 发烫：已经击穿，马上断电 |

不管量出来怎样，**这两片都建议直接换**。过压后的芯片可能今天还能用、明天就出错，时好时坏最难查。

## 第 4 步：M7C 坏没坏（回环测试）

1. 把 M7C 从 TTL 电路上拔下来，只留 USB。
2. 用一根杜邦线把 M7C **总线侧串口的 TX 脚和 RX 脚**直接连起来。
3. 打开串口助手，选它的 COM、波特率 1000000，发几个字节（比如 `55 AA 01`）。

| 结果 | 说明 |
|---|---|
| 发什么回什么 | M7C 和固件都正常 |
| 什么都不回，或者回的不对 | 串口脚坏了，换一块 M7C 再烧固件 |

## 第 5 步：修好以后的验收

换完芯片，先不接舵机，重做第 3 步的测量。都正常了再接舵机，跑：

```bat
uv run python <whj_MCU>\tools\orca\multibus\check_buses.py <whj_MCU>\tools\orca\multibus\buses.yaml
```

`RESULT: OK` 以后回到 `上机清单.md` 的第 4 步。

## 手头没有备用芯片时

多总线软件只认 COM 口，不关心 COM 口后面是什么。可以先用 **U2D2 顶替坏的那块电路**：一根手指走好的 M7C，另一根走 U2D2（只接 GND 和 DATA），`buses.yaml` 里把两个 COM 号写上。这样软件、两条数据线的接法、标定和开合都能先跑通。
“两个 MCU”这个目标本身还是要等第二块电路修好。

## 以后怎么避免

- 12V 只存在于电源板和舵机之间。面包板上永远只有 5V 和 3.3V。
- 从电源板出来的线只留 GND、VDD 两根，VDD 那根只进舵机。
- 每次改线后先断电用蜂鸣档量 VDD 对 5V、VDD 对 DATA：都不响再通电。
- 通电后第一件事量 5V 轨还是不是 5V。
