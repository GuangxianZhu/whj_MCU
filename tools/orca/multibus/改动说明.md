# 多块 M7C（multibus）：改了哪里、怎么在别的电脑上照做

日期：2026-11-15（11-11 初版，11-15 复查后更新）。
**没有接过实物。** 测试方式见第 8 节。上机步骤看同一文件夹里的 `上机清单.md`，这份是参考资料。

这几个文件都在本仓库的 `tools/orca/multibus/` 里。下面 `<whj_MCU>` 指你电脑上本仓库的文件夹。

## 1. 一共改了什么

**orca_core 里面**（由补丁完成）：

| 文件 | 动作 |

## 2. 在另一台电脑上怎么改

### 第 0 步：看那台电脑上的 orca_core

```bat
cd <orca_core 文件夹>
git status
git log -1 --format=%h
```

- 列出 `config.yaml`、`calibration.yaml`、`local_config.yaml`：正常，是你自己的设置。
- 列出 `orca_core/hardware_hand.py`：这个文件被改过，用方法二。
- 版本号是上面四个之一即可。

### 方法一：用补丁

补丁是一张“改动清单”，`git apply` 让 git 照着清单自动改。

```bat
git apply --check <whj_MCU>\tools\orca\multibus\multibus.patch
git apply <whj_MCU>\tools\orca\multibus\multibus.patch
```

第一条只检查、不改东西，没有任何输出就是能打上；然后再跑第二条。
报错时它不会改任何东西。可以再试一次 `git apply --ignore-whitespace <同一个路径>`；还不行就用方法二。
撤销：`git apply -R <同一个路径>`。

### 方法二：手动改

**(a) 复制 3 个文件**，从 `<whj_MCU>\tools\orca\multibus\` 到 orca_core 里：

- `multibus_client.py` → `orca_core\hardware\`
- `test_multibus_client.py` → `tests\`
- `test_multibus_wire_level.py` → `tests\`

**(b) 打开 `orca_core\hardware_hand.py`，改 3 处**

每一处都是“找到某一行，在它旁边粘贴一段”。粘贴的每一行前面都是 **8 个空格**，不能用 Tab。

**第 1 处**：搜索 `def _create_motor_client`，会搜到两个，改**第一个**（在 `class OrcaHand` 里，约 288 行）。在这一行的**下面**粘贴：

```python
        # --- multibus begin (local addition) ---
        from .hardware.multibus_client import create_multibus_client, is_multibus_port
        if is_multibus_port(self.config.port):
            return create_multibus_client(self.config)
        # --- multibus end ---
```

**第 2 处**：搜索 `return trial_probe(self.config, port)`（只有一处，约 298 行）。在这一行的**上面**粘贴：

```python
        # --- multibus begin (local addition) ---
        from .hardware.multibus_client import is_multibus_port, resolve_multibus_driver
        if is_multibus_port(port):
            return resolve_multibus_driver(self.config)
        # --- multibus end ---
```

**第 3 处**：搜索 `if isinstance(error, HandConfigValidationError):`（只有一处，在 `def connect` 里，约 430 行）。在这一行的**上面**粘贴：

```python
        # --- multibus begin (local addition) ---
        from .hardware.multibus_client import is_multibus_port
        if is_multibus_port(first_port):
            # Falling back to a single port would bring up one finger and
            # call it the hand; report the real problem instead.
            return False, f"Multibus connection failed: {error}"
        # --- multibus end ---
```

以后想知道改过哪里，在 `hardware_hand.py` 里搜 `multibus` 就能全部找到。想撤销，把这 3 段删掉即可。

**这 3 处各自是干什么的**

| 处 | 作用 | 不加会怎样 |
|---|---|---|
| 1 | 看到 `port: multibus` 就用“接线员”，否则照旧 | 永远走单总线 |
| 2 | 跳过官方的探测。官方只 ping 第一个和最后一个 ID（1 和 17） | 食指总线（7、8、9）上两个都没有，会报“没有电机应答” |
| 3 | 多总线连不上时直接报错，不去试别的 COM | 官方会自动换一个 COM 再试，结果只连上一根手指，还显示“连接成功” |

## 3. 改完先自检（不接硬件）

```bat
uv run --group dev pytest tests\test_multibus_client.py tests\test_multibus_wire_level.py
```

应该显示 `47 passed`，约 15 秒。

## 4. `buses.yaml` 怎么写

放在 `config.yaml` 的同一个文件夹里。两种写法，可以混用：

```yaml
baudrate: 1000000
parallel: false
buses:
  index:  [7, 8, 9]                         # 不写 COM：启动时自动找
  middle: {ids: [6, 17, 2], port: COM6}     # 写死 COM：不去找
```

| 项 | 意思 |
|---|---|
| `baudrate` | 舵机总线的波特率。这里写了就以这里为准，否则用 `config.yaml` 的 |
| `parallel` | `false` 一条一条轮流；`true` 每条总线一个线程同时进行 |
| 总线的名字 | 随便起，只在提示信息里用 |
| 不写 `port` | 启动时打开每个 USB 串口，ping 表里的 ID，谁回答谁就是这条总线。对不上就拒绝启动 |
| 写 `port` | 直接用这个 COM，不碰别的串口。COM 写错时那个口上没有这几个 ID，会拒绝启动并提示对调 |

`config.yaml` 里不要写中文（官方读它时用系统默认编码，日文 Windows 上可能读错）。`buses.yaml` 里可以写中文注释。缩进用空格，不要用 Tab。

## 5. 报错对照

| 终端里看到 | 意思 | 怎么办 |
|---|---|---|
| `routing table was not found` | `config.yaml` 旁边没有 `buses.yaml` | 把它放过去 |
| `is not valid YAML near line N` | `buses.yaml` 第 N 行附近格式错 | 多半是用了 Tab 或者没对齐 |
| `is not saved as UTF-8` | 文件被存成了别的编码 | 另存为 UTF-8，或者删掉中文注释 |
| `no port answered for bus 'index'` | 没有哪个 COM 回答 7、8、9 | 查 12V、DATA、GND、波特率；有没有别的程序占着串口。后面会列出每个 COM 回答了谁 |
| `bus 'index' on COM5: none of motor IDs ... answered ... the port may belong to another bus` | 写死的 COM 上没有这几个 ID | 把 `buses.yaml` 里两个 `port:` 对调；不是这个原因就查电源和接线 |
| `answers for motor IDs ... splits over buses` | 一个 COM 上同时有两根手指的电机 | 两条 DATA 连在一起了，查电源板 |
| `answers on both COMx and COMy` | 两块板接到了同一根手指 | 查接线 |
| `motor ID 8 is listed on both ...` | 表里同一个 ID 写了两次 | 改 `buses.yaml` |
| `motor IDs [...] are not in config.yaml` | 表里的 ID 这只手没有 | 改 `buses.yaml` |
| `motor IDs [...] are on no bus ... treated as not plugged in` | 只是提示：这些电机没有板子管 | 两根手指阶段是正常的 |
| `works on one bus at a time` | 扫描、改 ID、改波特率不能在多总线下做 | 把 `port:` 临时改回那条总线的 COM |
| `has no '...': it combines several buses` | 用到了接线员还没接的功能 | 把整段报错发给我 |

## 6. 它是怎么工作的（简版）

- **四类调用**：读全部（每条都读，按 1–17 的顺序拼回去）；带 ID 列表的写（按表拆开）；单个电机（只发给它所在的那条）；整体状态（全部都好才算好）。
- **每条总线下面是官方原来的驱动**，只是只管 3 个 ID。所以每块板上发生的事和你现在单块 M7C 时一样。
- **没有板子管的电机**：当作没插。官方本来就支持电机不在线，标定、预紧都会自动跳过对应的关节。
- **并行**：默认轮流。我用“每次读要等 20 ms 的假总线”测过：6 条轮流 121 ms，并行 21 ms。1 Mbps 下一条总线只要 1 ms 左右，先用轮流，实测不够快再把 `parallel` 改成 `true`。

## 7. 现在的限制

- 只支持 Dynamixel。
- 某一块板中途掉线时，没有“让其余手指一起停下”的保护。现在的表现（模拟串口上测过）：读数被标成不可靠；掉线那根停在原地；另一根继续工作；断开连接时会报出哪些电机没能关扭矩。
- 扫描电机、改 ID、改波特率、改 Return Delay 要一条总线一条总线地做（把 `port:` 改回那个 COM）。
- 多条总线之间不是同一时刻生效，会有很小的时间差。同一根手指的电机在同一条总线上，不受影响。
- 自动认 COM 会向电脑上每个 USB 串口发 ping。如果电脑上还插着别的串口设备，把 COM 号写死可以避免碰到它们。
- 以后更新 orca_core：先 `git stash`，更新，再 `git stash pop`，然后重新跑第 3 节的自检。
