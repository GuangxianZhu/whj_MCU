# 多块 M7C（multibus）：改了哪里、怎么在别的电脑上照做

日期：2026-11-11。对照 orca_core 提交 `48a38564`（2026-11-10）。
**只在假电机（官方自带的 Mock）上测过，没有接过实物。**

这几个文件都在本仓库的 `tools/orca/multibus/` 里。下面 `<whj_MCU>` 指你电脑上本仓库的文件夹。

## 1. 一共改了什么

| 文件 | 动作 | 说明 |
|---|---|---|
| `orca_core/hardware/multibus_client.py` | **新增** | “接线员”本体，830 行，全部是新文件 |
| `orca_core/hardware_hand.py` | **改 3 处，共加 17 行** | 官方文件里唯一被改的一个；没有删任何一行 |
| `tests/test_multibus_client.py` | **新增** | 31 个测试，不接硬件就能跑 |
| `buses.yaml` | **新增** | 路由表，放在你用的 `config.yaml` 旁边 |
| 你的 `config.yaml` | **改 1 行** | `port:` 改成 `multibus` |

路径都是从 orca_core 仓库的根目录算起（就是有 `scripts`、`tests` 这些文件夹的那一层）。

不写 `port: multibus` 时，这 17 行什么也不做，行为和官方原版完全一样。所以 U2D2、单块 M7C 的用法都不受影响。

## 2. 在另一台电脑上怎么改

### 第 0 步：先看那台电脑上的 orca_core 是什么状态

```bat
cd <orca_core 文件夹>
git status
git log -1 --format=%h
```

- `git status` 如果列出了被改过的文件（`modified:`），**先不要往下做**，把列表发给我。11-04 换 M7C 时另一个 Claude 在你电脑上改过东西，我不知道改了哪些。
- `git log` 显示的如果不是 `48a3856`，建议先切到这个版本：`git fetch origin` 然后 `git checkout 48a38564`。合成层是照这个版本的接口写的。

### 方法一：用补丁（最省事）

补丁是一张“改动清单”，`git apply` 让 git 照着清单自动改。在 orca_core 文件夹里运行：

```bat
git apply --check <whj_MCU>\tools\orca\multibus\multibus.patch
git apply <whj_MCU>\tools\orca\multibus\multibus.patch
```

第一条只检查、不改东西，没有任何输出就是能打上；然后再跑第二条。它会一次完成“新增 2 个文件 + 改 3 处”。我在一份干净的 `48a38564` 上试过，能直接打上。

报 `patch does not apply` 时它不会改任何东西，改用下面的方法二。想撤销：`git apply -R <同一个路径>`。

### 方法二：手动改（版本对不上、补丁打不上时用）

**(a) 复制 2 个文件**

从 `<whj_MCU>\tools\orca\multibus\` 复制到 orca_core 里：

- `multibus_client.py` → `orca_core\hardware\`
- `test_multibus_client.py` → `tests\`

**(b) 打开 `orca_core\hardware_hand.py`，改 3 处**

每一处都是“找到某一行，在它旁边粘贴一段”。粘贴的每一行前面都是 **8 个空格**，不能用 Tab。

**第 1 处**：搜索 `def _create_motor_client`，会搜到两个，改**第一个**（在 `class OrcaHand` 里，约 288 行）。在这一行的**下面**粘贴：

```python
            return create_multibus_client(self.config)
        # --- multibus end ---
```

```python

        return create_motor_client(
```

**第 2 处**：搜索 `return trial_probe(self.config, port)`（只有一处，约 298 行）。在这一行的**上面**粘贴：

**这 3 处各自是干什么的**

| 处 | 作用 | 不加会怎样 |
|---|---|---|
| 1 | 看到 `port: multibus` 就用“接线员”，否则照旧 | 永远走单总线 |
| 2 | 跳过官方的探测。官方只 ping 第一个和最后一个 ID（1 和 17） | 食指总线（7、8、9）上两个都没有，会报“没有电机应答” |
| 3 | 多总线连不上时直接报错，不去试别的 COM | 官方会自动换一个 COM 再试，结果只连上一根手指，还显示“连接成功” |

## 4. 怎么用

**(a) 放路由表**：把 `buses.yaml` 复制到你用的 `config.yaml` 所在的文件夹。两根手指的版本已经写好：

```yaml
baudrate: 1000000
parallel: false
buses:
  index:  [7, 8, 9]
  middle: [6, 17, 2]
```

**(b) 改 config.yaml 一行**：

```yaml
port: multibus
```

注意：`config.yaml` 里不要写中文。官方读这个文件时用的是系统默认编码，日文 Windows 上可能读错。`buses.yaml` 里可以写中文注释，我读它时固定用 UTF-8。

**(c) 命令和以前一样**。建议按这个顺序，从不会动到会动：

| 步 | 命令 | 会不会动 | 看什么 |
|---|---|---|---|
| 1 | `uv run python <whj_MCU>\tools\orca\bus_timing.py %CFG%` | 不会 | 两个 COM 被认对；`absent` 正好是没接的 11 个；失败次数 0 |
| 2 | `uv run python scripts\manual_control.py %CFG%` | 会，手动 | 食指、中指的滑块各自只动自己那根 |
| 3 | 其余官方脚本 | 会 | 没接的关节会被自动跳过 |

第 1 步的 `bus_timing.py` 不用改，我用两条假总线跑过它，能正常工作。

连接成功时终端里会有一行类似下面这样，写着每条总线落在哪个 COM、哪几个电机回答了：

```
multibus: index=COM5 [7, 8, 9], middle=COM6 [6, 17, 2]
```

想改回单总线：把 `port:` 改回原来的 COM 号即可，`buses.yaml` 留着不碍事。

## 5. 报错对照

| 终端里看到 | 意思 | 怎么办 |
|---|---|---|
| `routing table was not found` | `config.yaml` 旁边没有 `buses.yaml` | 把它放过去 |
| `no port answered for bus 'index'` | 没有哪个 COM 回答 7、8、9 | 查 12V、USB 线、波特率；有没有别的程序占着串口；后面会列出每个 COM 回答了谁 |
| `answers for motor IDs ... splits over buses` | 一个 COM 上同时有两根手指的电机 | 接线和表不一致 |
| `answers on both COMx and COMy` | 两块板接到了同一根手指 | 查接线 |
| `motor ID 8 is listed on both ...` | 表里同一个 ID 写了两次 | 改 `buses.yaml` |
| `motor IDs [...] are not in config.yaml` | 表里的 ID 这只手没有 | 改 `buses.yaml` |
| `motor IDs [...] are on no bus ... treated as not plugged in` | 只是提示：这些电机没有板子管 | 两根手指阶段是正常的 |
| `works on one bus at a time` | 扫描、改 ID、改波特率不能在多总线下做 | 把 `port:` 临时改回那条总线的 COM |
| `has no '...': it combines several buses` | 用到了接线员还没接的功能 | 把整段报错发给我 |

## 6. 它是怎么工作的（简版）

- **认 COM**：启动时把电脑上的 USB 串口挨个打开，ping 表里的 ID。谁回答了 7、8、9，谁就是 `index`。COM 号会随着插哪个 USB 口变，电机 ID 不会，所以按 ID 认。对不上就拒绝启动，不猜。
- **四类调用**：读全部（每条都读，按 1–17 的顺序拼回去）；带 ID 列表的写（按表拆开）；单个电机（只发给它所在的那条）；整体状态（全部都好才算好）。
- **没有板子管的电机**：当作没插。官方本来就支持电机不在线，会自动跳过对应的关节。
- **并行**：默认轮流。把 `buses.yaml` 里的 `parallel` 改成 `true` 就是每条总线一个线程。我用“每次读要等 20 ms 的假总线”测过：6 条轮流 121 ms，并行 21 ms。1 Mbps 下一条总线只要 1 ms 左右，先用轮流，实测不够快再开。

## 7. 现在的限制

- 只支持 Dynamixel。
- 某一条总线中途掉线时，没有做“让其余手指一起停下”的专门处理。现在的表现是：读数被标成不可靠，写入报错，和单总线掉线时官方的表现一样。测试时手边留着 12V 开关。
- 扫描电机、改 ID、改波特率、改 Return Delay 要一条总线一条总线地做（把 `port:` 改回那个 COM）。
- 多条总线之间不再是同一时刻生效，会有很小的时间差。同一根手指的电机在同一条总线上，不受影响。
- 以后更新 orca_core：先 `git stash`，更新，再 `git stash pop`，然后重新跑第 3 节的自检。自检不过就先别用新版本。
