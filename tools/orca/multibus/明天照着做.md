# 明天照着做（2026-11-17）

从上往下做，不用再查别的文档。每一步都写了“应该看到什么”，不对时怎么办写在同一格里。

**今天的状况**
- 软件已经改好，47 个测试全过。
- 硬件：舵机 3 针线中间那根（12V）接到了 TTL 板上，12V 进了板上的 5V。舵机用 U2D2 测过是好的，MCU 也确认没问题。
- TTL 电路已经焊在万能板上。TXB0104 模块和 74LVC2G241 转接板都插在排母上，M7C 用杜邦线连过来，两样芯片都有备用件。
- 全程只用万用表。

**所以办法很简单：两片都换新的。** 换之前先把板子改安全、确认电源正常，免得新芯片再被烧掉。

**这份文档怎么指位置**：万能板没有统一的孔号，所以全部用芯片自己的脚来说。

| 器件 | 脚 | 接的是什么 |
|---|---|---|
| TXB0104 模块（看板上丝印） | LV | 3.3V（来自 M7C） |
| | HV | 5V |
| | A1 / B1 | DIR（方向控制）。A 是 3.3V 一侧，B 是 5V 一侧 |
| | A2 / B2 | RX（接收） |
| | A3 / B3 | TX（发送） |
| | OE | 模块自己拉高，约 3.3V |
| 74LVC2G241 转接板（圆点是 1 脚） | 1 | 1OE，接 DIR |
| | 2 | 1A，接 DATA |
| | 3 | 2Y，接 DATA |
| | 4 | GND |
| | 5 | 2A，TX 进来 |
| | 6 | 1Y，RX 出去 |
| | 7 | 2OE，接 DIR |
| | 8 | VCC，5V |
| 舵机 3 针插座 | 1 / 2 / 3 | GND / VDD / DATA |

通道分配按仓库的电路图写（1 = DIR，2 = RX，3 = TX）。B 节会顺带验证这一点。

**量电压时**黑表笔一律放 GND（241 的 4 脚或舵机插座 1 号针）。

**要准备的**：万用表、1 根短杜邦线、电工胶带、手机（拍照）、备用的 TXB 模块和 241。

**大致时间**：A 到 E 约 1 小时。

## A. 把板子改安全（全部断电，10 分钟）

关电源板、断开 5V、拔 USB。舵机 3 针线从 TTL 板上拔下来。

| # | 做什么 | 为什么 |
|---|---|---|
| A1 | **拍照**：TXB 模块和 241 转接板插在排母上的样子，要能看清方向（丝印、圆点） | 新的要按同样方向插，插反会再烧一次 |
| A2 | 把 TXB 模块和 241 转接板都从排母上拔下来，贴上“旧”字放一边 | 先在空板上量电源，不拿新芯片冒险 |
| A3 | 接 TTL 板的那根 3 针线：把**中间那根线（2 号 VDD）从插头里退出来**，或者剪断后用胶带包好 | 这根线永远不该接到 TTL 板上。线不在了，就不可能再插错 |
| A4 | 蜂鸣档量 TTL 板上：舵机插座 **2 号针 ↔ 241 排母的 8 脚** | 响：板上 2 号针连着 5V，这就是 12V 进来的路。有条件就把这根连线焊掉；焊不掉也行，A3 已经把线去掉了 |
| A5 | 看板上接在 5V 和 GND 之间的电解电容：顶部有没有鼓；侧面印的耐压 | 它承受过 12V。鼓了，或者耐压是 10V、6.3V：换掉；没有备件就先拆掉 |
| A6 | 蜂鸣档：241 排母 **8 脚 ↔ 4 脚** | 不响。刚碰上时短促响一下是电容在充电，不算；一直响说明 5V 对地短路，先找到短路点 |

## B. 空板量电源（上电，不插芯片，不接舵机，5 分钟）

M7C 的杜邦线照常接着。电源板**不开**。先插 USB，再接 5V。

| # | 红表笔 | 应该 | 不对时 |
|---|---|---|---|
| B1 | 241 排母 8 脚 | 4.75–5.25 V | 见下面“5V 不对” |
| B2 | TXB 排母 HV | 4.75–5.25 V | 和 B1 不一样：板上 5V 的连线断了 |
| B3 | TXB 排母 LV | 3.0–3.6 V | M7C 的 3.3V 那根杜邦线没接好 |
| B4 | TXB 排母 A1（DIR） | 0–0.3 V | 约 3.3V：这根其实是 TX，说明通道分配和我写的不同，把 A1、A3 的角色对调着看 |
| B5 | TXB 排母 A3（TX） | 3.0–3.6 V | 0V：固件没在跑，或者 TX 那根杜邦线没接好 |
| B6 | 舵机插座 3 号针（DATA） | 4.5–5.25 V | 偏低：DATA 的 10k 上拉电阻坏了或虚焊 |

**5V 不对时**：断电，找到 5V 是从哪里进板子的（外部电源，或者 M7C 板的 5V 针），把它从板子上断开，单独量这个来源。来源不是 4.75–5.25V 就先解决它。**B1 不正常不要插新芯片。**

## C. 插上新芯片，静态检查（10 分钟）

断电。对照 A1 拍的照片，把**新的** TXB 模块和**新的** 241 插上，方向和照片一样。再上电（USB → 5V），电源板仍然不开，舵机不接。

这时固件处于空闲状态：DIR 是低，TX 是高。

| # | 红表笔 | 应该 | 说明什么 |
|---|---|---|---|
| C1 | 241 的 8 脚 | 4.75–5.25 V | 插上芯片后 5V 没被拉低 |
| C2 | TXB 的 OE | 3.0–3.6 V | 模块在工作 |
| C3 | TXB 的 B1 | 0–0.3 V | DIR 的低电平转到了 5V 侧 |
| C4 | TXB 的 B3 | 4.5–5.25 V | TX 的高电平从 3.3V 转成了 5V |
| C5 | 241 的 1 脚 和 7 脚 | 都是 0–0.3 V | 处于接收状态 |
| C6 | 舵机插座 3 号针（DATA） | 4.5–5.25 V | 总线空闲是高电平 |
| C7 | 241 的 6 脚 | 4.5–5.25 V | 接收缓冲把 DATA 的高传出来了 |
| C8 | TXB 的 A2 | 3.0–3.6 V | 接收通路一路通到 MCU 的 RX |
| C9 | 用短杜邦线把**舵机插座 3 号针接到 1 号针**（DATA 接地），再量 TXB 的 A2 | 0–0.3 V | 接收通路能传低电平 |
| C10 | 拿掉短线，再量 TXB 的 A2 | 3.0–3.6 V | 能回到高 |
| C11 | 通电 1 分钟后手指碰两片芯片 | 不烫 | |

C9 是安全的：DATA 上只有一个 10k 上拉，接地只流 0.5 mA。

有哪一项不对：断电，对照照片检查方向和有没有插歪一格。方向没错还是不对，把那一项的编号和读数发给我。

## D. 检查发送这条路（不接舵机，只用万用表，10 分钟）

C 节查的是空闲和接收。发送这条路平时是关着的，要让板子持续发数据才量得到。

原理：万用表显示的是平均电压。空闲时 DATA 一直是高，读数约 5V。让板子不停地发“全 0”的字节，DATA 大部分时间被拉低，读数就会明显掉下来。读数掉了，说明“电脑 → M7C → TXB → 241 → DATA”整条发送路是通的。

电脑上（在 orca_core 文件夹里打开命令行），先设三个变量，等号右边换成你的真实路径和 COM 号：

```bat
set WHJ=C:\你的路径\whj_MCU
set CFG=C:\你的路径\config.yaml
set COM1=COM5
```

运行发送测试。它会连续发 20 秒，这 20 秒里去量：

```bat
uv run python %WHJ%\tools\orca\multibus\tx_test.py %COM1%
```

| # | 什么时候 | 红表笔 | 应该 |
|---|---|---|---|
| D1 | 运行前 | 舵机插座 3 号针（DATA） | 约 5 V |
| D2 | 发送的 20 秒里 | 舵机插座 3 号针（DATA） | 明显低于 5 V，一般在 0.5–3.5 V 之间 |
| D3 | 发送的 20 秒里 | 241 的 7 脚 | 明显高于 0 V，一般在 1.5–5 V 之间 |
| D4 | 结束后 | 舵机插座 3 号针（DATA） | 回到约 5 V |

20 秒不够就再运行一次，或者在命令后面加 `--seconds 60`。

| 量到的 | 说明 | 怎么办 |
|---|---|---|
| D2、D3 都对 | 发送路是通的 | 进 E |
| D2 一直是 5 V，D3 一直是 0 V | 方向信号没出来 | 查 DIR 那根杜邦线；再量 TXB 的 A1，发送时应该高于 0 V。A1 有变化而 B1 没变化：TXB 没插好 |
| D2 一直是 5 V，D3 是对的 | 方向开了，数据没出来 | 发送时量 TXB 的 B3，应该明显低于 5 V。B3 低了而 DATA 不低：241 没插好。B3 也不低：查 TX 那根杜邦线 |
| 命令报 `Could not open` | COM 被占用或 COM 号写错 | 关掉串口助手，核对 COM 号 |

这个测试发的是全 0，舵机不认识这种数据，所以它只用来量电平。测的时候不要接舵机。

## E. 接回舵机，单总线验证（15 分钟）

**接线**：和出事前一样，但只有两根线。
- 1 号 GND → TTL 板舵机插座 1 号针
- 3 号 DATA → TTL 板舵机插座 3 号针
- 2 号 VDD：已经在 A3 去掉了

**上电前**（全断电）：

| # | 蜂鸣档 | 应该 |
|---|---|---|
| E1 | TTL 板的 DATA ↔ GND | 不响 |
| E2 | 电源板的 VDD ↔ TTL 板 241 的 8 脚 | 不响 |
| E3 | 电源板的 VDD ↔ TTL 板的 DATA | 不响 |
| E4 | 电源板的 GND ↔ TTL 板的 GND | 响 |

上电顺序：**USB → 5V → 电源板**。断电顺序反过来。

| # | 红表笔 | 应该 | 不对时 |
|---|---|---|---|
| E5 | 241 的 8 脚 | 4.75–5.25 V | 高于 5.25V：**马上关电源板**，12V 又进来了 |
| E6 | DATA | 约 5 V | |

只读检查，手不会动：

```bat
uv run python %WHJ%\tools\orca\multibus\check_buses.py --ports %COM1%
```

应该看到 `answered: ID 1 (model ...), ID 2 ...`，接了几个舵机就有几个 ID。

再把 `config.yaml` 的 `port:` 写成这块板的 COM 号（出事前的写法），跑读数测试：

```bat
uv run python %WHJ%\tools\orca\bus_timing.py %CFG%
```

最后一行要是 `stale / failed reads: 0`。到这里，这块 TTL 板就修好了，可以像以前一样控制整只手。

| 结果 | 怎么办 |
|---|---|
| ID 都回答，失败次数 0 | 进 F |
| 一个 ID 都不回答 | 先看电源板开了没有、DATA 和 GND 两根线插对没有；再重做 C6–C10 和 D |
| 只有一部分 ID 回答 | 没回答的那几个舵机的线松了 |
| ID 都回答，但失败次数不是 0 | GND 那根线接触不好，或者 DATA 线太长太松；重插后再跑 |

## F. 两根手指、两块 MCU

这一步需要**两块** TTL 板。

### F1. 第二块 TTL 板

第二块板没有碰过 12V，芯片不用换。对它做这几项：
- **A3、A4**：把它那根 3 针线的中间线去掉。这一条最要紧，否则同样的事会再发生一次。
- **C**（芯片插着直接量）和 **D**。

还没焊好、来不及的话，用 U2D2 顶替，见最后一节。

### F2. 接线（全断电）

```
12V 电源 ── 电源板 ──┬── VDD、GND ──> 食指 3 个舵机（7、8、9）
                     └── VDD、GND ──> 中指 3 个舵机（6、17、2）

TTL 板 1 的 DATA（3 号针） ──> 食指舵机的 DATA
TTL 板 2 的 DATA（3 号针） ──> 中指舵机的 DATA

两块 TTL 板的 GND（1 号针） ──> 电源板的 GND
```

要点：两根手指的 DATA **不能经过电源板**。电源板的几个 TTL 口，DATA 是并在一起的。从电源板到手指的线只留 GND、VDD 两根。

| # | 蜂鸣档 | 应该 |
|---|---|---|
| F2a | 食指 DATA ↔ 中指 DATA | 不响 |
| F2b | 每条 DATA ↔ 电源板 VDD | 不响 |
| F2c | 每块 TTL 板 241 的 8 脚 ↔ 电源板 VDD | 不响 |
| F2d | 每块 TTL 板的 GND ↔ 电源板 GND | 响 |

### F3. 只读检查

上电（两个 USB → 两路 5V → 电源板），再量一次两块板 241 的 8 脚，都要是约 5V。

```bat
uv run python %WHJ%\tools\orca\multibus\check_buses.py %WHJ%\tools\orca\multibus\buses.yaml
```

结尾应该是：

```
  OK: bus 'index' [7, 8, 9] is on COM5
  OK: bus 'middle' [6, 17, 2] is on COM6
RESULT: OK
```

它还会打印一份填好 COM 号的表，下一步用。

| 看到 | 怎么办 |
|---|---|
| `answer on more than one port` | 两条 DATA 连在一起了，回 F2 |
| `no port answered for it` | 那一块板不通：查它的 USB、DATA、GND，对它重做 B–D |
| `no motor answered on any port` | 电源板开了没有；有没有串口助手占着 COM |

### F4. 改两个设置文件

在 `config.yaml` 的同一个文件夹里新建 `buses.yaml`，内容用 F3 打印的那一份：

```yaml
baudrate: 1000000
buses:
  index: {ids: [7, 8, 9], port: COM5}
  middle: {ids: [6, 17, 2], port: COM6}
```

`config.yaml` 里把 `port:` 那一行改成：

```yaml
port: multibus
```

### F5. 连接读数（不会动）

```bat
uv run python %WHJ%\tools\orca\bus_timing.py %CFG%
```

要看到：

```
multibus: index=COM5 [7, 8, 9], middle=COM6 [6, 17, 2]
connect: True Connection successful (dynamixel @ multibus, 1000000 baud)
...
stale / failed reads: 0  (should be 0)
```

黄色警告说其余 11 个关节没有应答，是正常的。

### F6. 两根手指一起动

手放在电源板开关旁边。先小角度：

```bat
uv run python %WHJ%\tools\orca\multibus\two_finger_demo.py %CFG% --close-deg 25 --cycles 2
```

正常以后加大：`--close-deg 50 --cycles 5`。随时按 Ctrl+C 停，停的时候会关扭矩。

### F7. 标定和预紧（需要时才做）

先把 `config.yaml` 所在的文件夹复制一份到桌面当备份。

```bat
uv run python scripts\calibrate.py %CFG% --fingers index middle
uv run python scripts\tension.py %CFG%
```

标定会把这两根手指推到机械限位。`tension.py` 按 Ctrl+C 结束。

## 第二块板来不及时：用 U2D2 顶一条线

多总线软件只认 COM 口。食指走修好的 TTL 板，中指走 U2D2：

- U2D2 的 3 针线：1 号 GND → 电源板 GND；3 号 DATA → 中指舵机的 DATA；2 号 VDD 不接。
- 其余和 F2–F7 一样，`buses.yaml` 里 `middle` 的 `port` 写 U2D2 的 COM 号。

这样软件、接线方式、标定、两指开合都能跑通。“两块 MCU”要等第二块板。

## 旧的两片芯片

全部跑通以后，想知道哪一片坏了，可以每次只换回一片旧的，跑一次 E 节的 `check_buses.py`。换回去就不通的那一片是坏的。测完都换回新的，旧的不要再用，哪怕它看起来还能工作。

## 想退回原来的用法

`config.yaml` 的 `port:` 改回 COM 号即可，其它都不用动。
